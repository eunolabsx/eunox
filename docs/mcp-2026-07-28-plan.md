# MCP 2026-07-28 conformance plan

**Status:** in progress. §1 (the negotiation spine) has landed; nothing else has.
**Targeted spec today:** 2025-11-25. **Planned target:** 2026-07-28 alongside it.
**Verified against:** eunox @ `5dba99c` — the state this plan was written against.
Its body is left as authored, describing the work from that starting point; the
current state of each item, and where what landed differs from what was proposed,
lives in [mcp-2026-07-28-execution.md](mcp-2026-07-28-execution.md).

The 2026-07-28 revision is the published stable specification, not a release
candidate. It is the largest MCP revision since launch: it removes the protocol
session and the `initialize` handshake, replaces server-initiated requests with a
retry pattern, replaces the standalone SSE endpoint with a subscription stream,
moves tasks into an extension, and adds required result-caching metadata.

This document states what changes, what it costs eunox, the decisions that must be
made before code, and the order the work has to happen in. It covers the OSS data
plane only.

References in this document name a **file and a symbol, never a line number**.

---

## The shape of the problem

eunox is a proxy. It sits between a host and an upstream that will migrate at
different speeds, and it must keep enforcing while they do. Three consequences
follow, and they drive everything below:

1. **Revision is a per-peer property, not a build constant.** One binary
   negotiates independently with the host and with the upstream.
2. **A removed method is not the same as an unknown method.** `ping`,
   `resources/subscribe`, `resources/unsubscribe`, and `logging/setLevel` are
   dispatched today. Under 2026-07-28 they do not exist. The dispatch tables must
   become revision-scoped so that "removed here, still live there" is expressible
   without weakening the fail-closed default in either direction.
3. **Two enforcement points move from the request path to the response path.**
   Sampling and elicitation stop being upstream-initiated requests and become
   `inputRequests` on a result eunox already allowed. eunox's deny lever for them
   has to move with them.

### What is safe today, and the one thing that is not

An unmapped 2026-07-28-only method (`server/discover`, `subscriptions/listen`,
`tasks/*`) hits `dispatchUnmapped` in `internal/transport/dispatch.go` and is
denied. A 2026-07-28 host gets denials, never bypass, for those methods.

`tools/call`, `resources/read`, and `prompts/get` are a different case: they exist
in both revisions, so a 2026-07-28 request for one of them is **dispatched and
enforced today**, with eunox ignoring the new `Mcp-Method` / `Mcp-Name` headers and
the required `_meta` protocol version. eunox's own decision stays correct — it has
always decided on the body — but eunox forwards a request whose headers it never
checked against that body. Under 2026-07-28 a disagreeing pair is an error
(`HEADER_MISMATCH`, -32020), and any component metering on those headers rather
than the body will meter the wrong thing. Verifying that pair is the one item in
this plan that is a hardening fix rather than a compatibility gap.

## What changes, and what it costs

### Breaking, with direct eunox impact

| Spec change | eunox impact |
|---|---|
| `initialize` / `notifications/initialized` removed; every request carries `_meta` `io.modelcontextprotocol/protocolVersion` and `io.modelcontextprotocol/clientCapabilities` | Load-bearing. eunox's whole HTTP session lifecycle is initialize-anchored: `registerSession`, the decision-turn pin, the upstream subprocess spawn, the identity claims captured for the server-initiated leg, and the `--require-audit=strict` gate all hang off the session-creating `initialize` in `internal/transport/http_routing.go`. With no handshake, session creation must become implicit on first request and keyed on bearer identity. |
| `Mcp-Session-Id` removed | Low. `httpSession` is eunox's own UUID-keyed construct; the header is a correlation convenience. `upstreamSessID` (`internal/transport/http_remote.go`) becomes dead for 2026-07-28 upstreams. |
| Server-initiated requests replaced by multi round-trip requests: results carry `resultType: "input_required"` with `inputRequests` and/or an opaque `requestState`; the client retries with `inputResponses` | Largest single item. `sampling/createMessage` is an enforced method today and `roots/list` / `elicitation/create` are forwarded-and-audited; all three stop being requests eunox can decide on the request path. The deny lever moves to the response path. See *The re-decision problem* below. |
| Standalone GET endpoint and `resources/subscribe` / `resources/unsubscribe` replaced by `subscriptions/listen` | Two currently-enforced methods lose their wire. `DecideResourceCancel` in `internal/pdp/pdp.go` exists specifically to authorize `resources/unsubscribe` by match alone; its semantics need a new home in stream teardown. |
| `ping`, `logging/setLevel`, `notifications/roots/list_changed` removed | `ping` is in `locallyAnsweredHandlers`; `notifications/roots/list_changed` is in `forwardableHostNotifications`. Both must become revision-scoped. `logging/setLevel` is already denied as unmapped, so nothing to remove. |
| All results require `resultType`; absent means `"complete"`. The type is an **open** union (`"complete"` \| `"input_required"` \| `string`) | Every result eunox synthesizes or rewrites must carry it for 2026-07-28 peers: the response builders in `internal/mcp`, the filtered lists from `dispatchList`, and the discovery response. Because the union is open, an unrecognized *present* value is an ambiguity and must be refused fail-closed — only an *absent* field reads as `"complete"`. |
| SSE resumability removed (`Last-Event-ID`, event ids) | **No action.** eunox never implemented resumability. |
| Tasks moved to the `io.modelcontextprotocol/tasks` extension; `tasks/get` polling replaces `tasks/result`; `tasks/update` added; `tasks/list` removed | Tasks are unmapped in both directions today. This is new enforcement, not a migration. |
| JSON-RPC server-error range partitioned: -32000..-32019 implementation-defined, -32020..-32099 reserved; resource-not-found -32002 to -32602 | Net improvement. See *Error codes* below. |

### Non-breaking, with direct eunox impact

| Spec change | eunox impact |
|---|---|
| `server/discover` added, implementation mandatory | Replaces the `buildInit` seam. Discovery output is a capability enumeration and must go through the **same identity filtering the `*/list` methods get**, or it becomes a discovery bypass around `FilterToolsList`. |
| `Mcp-Method` and `Mcp-Name` required on Streamable HTTP POST | eunox is precisely the gateway these exist for. Must verify header against body (fail closed, `HEADER_MISMATCH`) on the host leg and emit them on the upstream leg. |
| `x-mcp-header` custom-header passthrough | New header-smuggling surface through a proxy. Needs an explicit allowlist decision; default should be to strip. |
| `ttlMs` and `cacheScope` (`public` \| `private`) required on list results and `resources/read` | eunox serves identity-filtered views, so any response it filtered must be clamped to `private`. Already tracked as threat-model finding L-6. |
| Tools from `tools/list` should be returned in deterministic order | `filterListResult` preserves upstream order and sibling fields; needs an assertion test, not a change. |
| `extensions` field on `ClientCapabilities` / `ServerCapabilities` | Discovery response must carry it; the tasks extension is advertised through it. |
| `inputSchema` / `outputSchema` accept any JSON Schema 2020-12 keywords, including `$ref`; `structuredContent` accepts any JSON value | Affects Tier-2 interface pinning: `SurfaceHash` in `internal/pdp/surface_pin.go` hashes `inputSchema` / `outputSchema` directly, so a semantically identical surface expressed with `$ref` hashes differently and trips a sticky per-session break. `$ref` resolution is also a fetch surface eunox must not perform. |
| OpenTelemetry trace context in `_meta` (`traceparent`, `tracestate`, `baggage`) | Passthrough discipline; also the blessed stateless mechanism for delegation observability. |
| Authorization: `iss` per RFC 9207, `application_type` in DCR, credentials bound to the issuing AS | Token-acquisition layer. eunox consumes tokens rather than issuing them, so mostly out of scope; the existing audience validation and claim-schema gate absorb any movement. |

### Deprecated, with a dated clock

Roots, Sampling, Logging, and OAuth Dynamic Client Registration are deprecated as
of 2026-07-28 with **earliest removal on or after 2027-07-28**. The HTTP+SSE
transport is removable three months after SEP-2596 reaches Final.

**Elicitation is not on that list.** `elicitation/create` remains a live,
undeprecated request type carried as an `inputRequests` payload, so it outlives
the removal window that retires sampling and roots — which makes it the durable
MRTR payload, and the one eunox has no deny lever for today.

That date is the retirement clock for eunox's entire server-initiated request
subsystem — `forwardServerRequest`, `serverRequestPool`, the `samplingTurnWait`
bound, and the `spansAnchors` refusal. None of it can be deleted before then
because 2025-11-25 peers still need it, and all of it should be scoped to that
revision now so the deletion is a subtraction rather than an untangling.

## Decisions to make before code

These four are not implementation details. Each one changes the shape of the work.

**1. Does eunox translate between revisions, or require the two peers to agree?**

Strict pass-through — refuse a mismatched host/upstream pair at startup or at the
first request — is small, obviously correct, and gives up the thing a proxy is for.
Translation makes eunox a revision shim and lets the two sides migrate
independently, which is the stronger position, but MRTR and the server-initiated
leg are not losslessly translatable in either direction.

Recommended: **translate the `tools/call` / `*/list` / `resources/read` /
`prompts/get` path, refuse the mismatched pair for anything involving MRTR or
subscriptions.** That covers the common deployment (a modern host in front of a
lagging upstream) without pretending a stateless client can service a
server-initiated request.

**2. How is an MRTR retry metered?** See below; this one has a security answer, not
just an ergonomic one.

**3. Where does session creation anchor once `initialize` is gone?** ADR-0004
answers this for correlation and revocation. It also has to answer it for
*creation*, which the current draft does not: the first request on a connection
must be able to mint the internal session, spawn the upstream, and pass the
`--require-audit=strict` gate. Until that is settled, no 2026-07-28 request can be
served at all on the HTTP transport.

**4. Does `server/discover` reuse the list filters or get its own?** Reusing
`FilterToolsList` / `FilterResourcesList` / `FilterPromptsList` keeps one filtering
implementation and one place to get identity scoping wrong. It should reuse them.

### The re-decision problem

A `tools/call` that returns `resultType: "input_required"` and is then retried with
`inputResponses` is **two `tools/call` requests on the wire for one logical call.**
Nothing in eunox distinguishes them today, so the retry would:

- charge `maxCalls` and any cumulative `blastRadius` budget a second time
  (`pkg/callcounter`, `AdmitAll`);
- commit a second `sequenceBlock` antecedent;
- apply flow labels a second time.

A long MRTR exchange would exhaust a budget sized for the calls the operator
actually intended to permit. Under-counting is equally wrong in the other
direction: treating every retry as free lets a caller launder unlimited work
through one admitted call.

The spec provides the seam: `requestState`, an opaque blob the server mints and the
client returns. The proposal is that eunox **wraps** the upstream's `requestState`
in its own signed continuation — binding the original decision, its anchor, and the
quota already committed — and on the retry verifies that binding, re-runs the
match and kill checks, and commits quota **once**. The continuation is
client-carried and signed rather than stored, which keeps it inside the stateless
posture: no shared store, any instance can verify it.

Open sub-questions: continuation lifetime; whether a retry may present a
continuation minted for a different anchor (no); and whether the effect ceiling and
`effectClass` conditions re-evaluate per round trip or only on the first (they
should re-evaluate, since `inputResponses` can change arguments).

## The work, in dependency order

### 1. The negotiation spine — **LANDED**

Nothing else can be written until a request's revision is a known value.

> Landed. Two details differ from the proposal below: a context pins its revision from
> its FIRST resolved message rather than from the `initialize` params (pinning at the
> handshake would never fire for a peer on the revision that removed it), and the
> `_meta` declaration is read by decoding the params rather than probing for the key.
> See the execution plan's W1 for the full account.

- `MCPProtocolVersion` in `internal/transport` becomes a supported-revision set,
  negotiated per peer, with the host-side and upstream-side results tracked
  independently.
- Determine a request's revision from `_meta` `io.modelcontextprotocol/protocolVersion`
  (required in 2026-07-28) and fail closed on absence for a peer that negotiated
  the new revision, with `UNSUPPORTED_PROTOCOL_VERSION` (-32022) where the spec
  calls for it.
- `decideMethodHandlers` and `locallyAnsweredHandlers` in
  `internal/transport/dispatch.go` become revision-scoped. A method absent from the
  table for the requesting peer's revision falls to `dispatchUnmapped` exactly as
  today, so removal is expressed by the same fail-closed default that already
  covers unknown methods, rather than by a second mechanism.
- `forwardableHostNotifications` gets the same treatment, so
  `notifications/roots/list_changed` stops being forwardable for 2026-07-28 peers.

This is also the minimum forward-compatible seam: it can land ahead of any
conformance work, and every later item plugs into it.

### 2. Bearer-identity anchoring (ADR-0004)

Blocking for the HTTP transport, as noted above. Correlation on the credential
identity, stateful policy keyed on the stable `agent_id` / `task_id`, and session
creation on first request rather than on `initialize`. `jti` is parsed but
deliberately not decoded today (`internal/pdp/jwt.go`); carrying it into
`JWTClaims` is the prerequisite for revocation on the finest unit.

### 3. Header verification and emission

- Require `Mcp-Method` and `Mcp-Name` on 2026-07-28 POSTs; verify both against the
  parsed body; on disagreement or a missing/malformed header, return
  `HEADER_MISMATCH` (-32020) and record it. A mismatch is an enforcement-confusion
  attempt and should be audited as such, not as a parse error.
- Emit both headers on the upstream leg.
- Decide the `x-mcp-header` posture (recommend: strip unless explicitly
  allowlisted) and document it in the threat model.
- Retire `Mcp-Session-Id` from the host-facing surface while keeping the internal
  `httpSession`.

### 4. `server/discover`

- A responder routed through `dispatchRequest` — not answered outside it, the way
  HTTP's session-creating `initialize` is today — so it inherits the shared kill
  gate by construction.
- Output filtered through the same `ListFilterer` methods the `*/list` path uses.
- `buildInit` generalizes to a revision-selected responder; `initialize` stays for
  2025-11-25 peers.
- Advertise `extensions`.

### 5. Result-shape and caching invariants

- Emit `resultType` on every result eunox synthesizes or rewrites, for
  2026-07-28 peers.
- Clamp `cacheScope` to `private` on any response eunox filtered; never preserve an
  upstream `public`. Preserve `ttlMs` as a freshness hint. This closes L-6.
- Add an assertion test that `filterListResult` preserves upstream ordering.

### 6. Multi round-trip requests

The signed-continuation design above, plus:

- Inspect `inputRequests` on an allowed call's result and apply the sampling deny
  lever there. The manifest surface stays `system:sampling/createMessage`; what
  changes is where it is evaluated. An `inputRequest` the manifest does not permit
  is denied or stripped rather than forwarded to the host.
- Scope the existing server-initiated subsystem to 2025-11-25 and leave it
  otherwise untouched.

### 7. `subscriptions/listen`

- Treat the stream open as an enforced action bound to the opener's anchor,
  decided per URI for the `resourceSubscriptions` set, so a subscription cannot
  reach a resource the caller could not `resources/read`.
- Filter notifications delivered on the stream against the opener's identity and
  policy, exactly as list discovery is filtered.
- Rehome `DecideResourceCancel`'s match-alone semantics onto stream teardown and
  subscription-set narrowing, preserving the property that gave it its shape: a
  cancel must not be refusable by a spent budget, since that would strand the
  stream the subscribe opened.
- Demote the standalone GET endpoint for 2026-07-28 peers.

### 8. Tasks extension

- Dispatch entries for `tasks/get`, `tasks/update`, and `tasks/cancel`.
- Deferred effects inherit the initiating call's anchor, with the antecedent
  committed at forward time.
- Reconcile `tasks/cancel` with the kill path, and decide whether a killed session's
  outstanding tasks are cancelled or merely unreachable.

### 9. Error codes

eunox's denial codes (-32001 `AUTHORIZATION_FAILED` / `KILL_SWITCH`, -32002
`CAPABILITY_DENIED`, -32003 `CONDITION_FAILED`) sit inside the new
implementation-defined range -32000..-32019 and are **already legal** under the new
partition. The renumbering is a net improvement: under 2025-11-25 those codes
collided with the spec's own `HeaderMismatch` (-32001), `MissingRequiredClientCapability`
(-32003), and resource-not-found (-32002), so a host could not reliably tell an
eunox denial from a protocol error. That ambiguity disappears.

Remaining work is narrow: track resource-not-found to -32602, keep every eunox code
out of -32020..-32099 permanently, and make `IsInfraDenialCode` revision-aware.
Worth an explicit test that pins the codes inside the implementation-defined range,
so a future addition cannot drift into reserved space.

### 10. Tier-2 surface pinning under the new schema rules

`SurfaceHash` hashes `inputSchema` and `outputSchema` as given. With arbitrary JSON
Schema 2020-12 keywords and `$ref` now permitted, an upstream that refactors a
schema into `$ref` form without changing its meaning trips a sticky per-session
interface break. Options: canonicalize before hashing, hash a resolved form, or
accept the false positive and document it. eunox must not fetch a remote `$ref`
under any option; a schema containing one should be refused rather than resolved.

### 11. CLI probe and drift path

`validate --live`, `init`, and `drift.MakeDriftCheck` all open with `initialize`.
An upstream that moves to `server/discover` breaks drift checking and onboarding.
Same dual-revision treatment as the proxy path. This one is outside the request
path and correspondingly easy to forget.

### 12. Documentation

- `docs/conformance.md`: grow the 2026-07-28 disposition table to cover every row
  above, and flip the targeted-spec line once the global conformance criteria
  hold. (The release-candidate framing was corrected when this plan landed.)
- `docs/threat-model-mcp.md`: L-6 mitigation, the header/body confusion vector, the
  MRTR re-decision problem, and the `x-mcp-header` posture.
- `docs/interface-pinning-tier2.md`: the `$ref` hashing decision.
- ADR-0004 needs the session-creation half added, and either promotion or an
  explicit note that it stays Draft pending the published-revision details it was
  waiting on — those details are now published.

## Needs no action

- **SSE resumability removal.** Never implemented.
- **HTTP+SSE transport deprecation.** eunox already speaks Streamable HTTP.
- **OAuth DCR deprecation.** Never implemented; the RFC 9728 protected-resource
  metadata surface is unaffected.
- **Roots and Logging deprecation.** `roots/list` is forwarded rather than enforced
  and `logging/setLevel` is already denied as unmapped; both follow the 2027-07-28
  clock with the rest of the old revision.
- **MCP Apps.** UI templates ride `resources/read`, UI-initiated execution is an
  ordinary `tools/call`, and the `ui/*` bridge never traverses the proxy. A future
  server-transport `app/*` method would hit the fail-closed unmapped path and need
  classification.
- **Deterministic list ordering.** Already preserved; add the test.

## Sequencing

Items 1 and 2 are the forward-compatible seams and gate everything else; item 2 is
a hard blocker for the HTTP transport rather than a hedge. Items 3 through 7 and 9
and 11 constitute functional conformance. Items 8 and 10 can follow. Item 12 tracks
each of them in the same change, per repository convention.
