# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`eunox` is a policy-enforcement proxy for MCP servers (Go, one static binary). It sits between an MCP host and an upstream MCP server, checks every enforced MCP method (`tools/call`, `resources/read`, `resources/subscribe`, `resources/unsubscribe`, `prompts/get`, `sampling/createMessage`) against a YAML capability manifest before forwarding, filters `*/list` responses to permitted entries, and writes every decision to an HMAC-SHA256-signed OCSF JSONL audit log.

## Commands

```bash
make build           # → bin/eunox
make test            # go test -race -count=1 ./...
make lint            # go vet + golangci-lint at CI's pinned version (installs it when PATH has another)
make fmt             # gofmt -w every .go file
make check-fmt       # gofmt-clean check on every .go file (CI-enforced); fix with `make fmt`
make check-license   # Apache-2.0 SPDX header on every .go file (CI-enforced)
make check-notice    # NOTICE lists exactly the binary's third-party modules (CI-enforced)
make coverage        # coverage.out for all packages — CI gates pkg/, internal/ and cmd/ at 80% each
```

Run a single test (standard Go tooling):

```bash
go test -race -count=1 -run 'TestName' ./cmd/eunox/
```

End-to-end demo stack (Docker) — the fastest way to verify a behavior change against a real proxy + mock upstream: `make -C demo up`, then `make -C demo allow|deny|audit`; gateway variant `make -C demo gateway-up`.

## Architecture

Three layers: `cmd/eunox/` is the binary (CLI, transport wiring, PDP wiring); `pkg/` holds the importable engine and supporting libraries; and `internal/` holds subsystems factored out of the binary behind narrow seams — `internal/audit` (the tamper-evident audit log, consumed through the exported `audit.Sink`), `internal/mcp` (the MCP protocol message types plus the JSON-RPC envelope/newline-framing/classification layer — `RPCMsg`, `MsgReader`/`MsgWriter`, `MsgKey`, the response builders — shared by the transports, PDPs, and the CLI's live-upstream probe), `internal/pdp` (the policy decision points: the `PolicyDecisionPoint` contract and the `ManifestPDP`/`JWTPDP`/`AlwaysAllowPDP` implementations), `internal/config` (the config + manifest loading layer: `GatewayConfig` parsing, `LocalManifest` load/validate/merge, schema-version negotiation), `internal/drift` (the startup manifest-drift-comparison policy: `CheckManifestDrift`/`MakeDriftCheck`/`UpstreamTool`/`Warning`/`ParseToolsListResult`/`CheckFunc`, shared by the binary's `validate --live` and the transport runtime), `internal/registry` (the effect-contract corpus format — `Contract`/`LoadCorpus`/`Validate` — plus the attestation trust layer in `attest.go` — `Signature`/`TrustStore`/`LoadTrustStore`/`VerifyAttestations`/`AttestationPayload` — over the shipped corpus in `registry/contracts/`; authoring-time input only, never consulted on the decision path, and no key is ever fetched), and `internal/transport` (the stdio + HTTP/gateway transport runtime — the proxies, the shared dispatch/forward/enforcement core, the remote-upstream bridge, the route wiring, and the control-token/OAuth-metadata/health endpoints; the binary just wires it). The layering is `internal/mcp` ← `internal/pdp` ← `internal/transport` ← the binary, with `internal/audit` below the transport but deliberately NOT below the PDP layer (the caller-identity adapter that joins the two — validated claims to the `audit.Identity` a record stamps — lives in the binary, `cmd/eunox/audit_identity.go`, which is the one place that already imports both; having `internal/pdp` return the writer's own struct satisfied the `WithIdentity` seam by inverting its arrow rather than removing it, and made every consumer of the PDP layer link the audit writer), and with `internal/config` and `internal/drift` sibling lower layers (`internal/drift` builds on `internal/{config,mcp,pdp}` + `pkg/{capability,enforcement}`) imported by both the CLI and the transport layer; `internal/transport` builds standalone on `internal/{audit,config,drift,mcp,pdp}` + `pkg/*` with zero references back into the binary.

**Request flow:** host JSON-RPC request → transport layer parses method + arguments → `PolicyDecisionPoint.Decide(...)` → allow: forward to upstream; deny: structured JSON-RPC error back to host (upstream never called) → either way, an audit record is written.

### cmd/eunox

- **Transports** — their own package `internal/transport`; the binary just constructs the proxies (`transport.NewStdioProxy`/`transport.NewHTTPProxyGateway`) and calls `.Start`/`.Serve`. `stdio.go` (`StdioProxy`: host on stdin/stdout, one upstream as subprocess or remote HTTP via `stdio_http_upstream.go`); the `http*.go` files (`HTTPProxy`: MCP Streamable HTTP/SSE, one upstream subprocess per client session, `Mcp-Session-Id` header, loopback-only `/control/kill`) — split by concern into `http.go` (server core: construction + `Serve`), `http_routing.go` (`/mcp` POST/GET/DELETE + `/control/kill`), `http_security.go` (auth, Origin/DNS-rebinding, source-IP, loopback), `http_session.go` (`httpSession` lifecycle, registry, idle reaper, upstream I/O, SSE broadcast; killed-session reclaim runs on the kill's own DELIVERY — `killswitch.Manager.ObserveRevocations` wakes `reclaimOnRevocation`, which re-asks the kill switch about each held session — with the idle reaper's killed arm as the backstop it cannot be, since that reaper does not run at all under `sessionIdleTimeoutMs: 0`), and `http_handlers.go` (upstream-timeout/denial helpers + server-initiated request handling); `record_limiter.go` holds the admission control over the refusal records whose write rate a caller sets — the `recordRateLimiter` token bucket (instantiated proxy-wide for pre-session refusals) and the per-pool `saturationGate` that collapses a `RESOURCE_EXHAUSTED` flood to one record per saturation episode. Both transports route enforced requests through one shared `dispatchRequest` (`dispatch.go`: the method→handler mapping and fail-closed default) and the shared deny/forward/record core (`forward.go`: `enforcedForwardCore`/`forwardServerRequest`), so the dispatch and enforcement logic live once instead of being hand-mirrored per transport; `serialize.go` + `anchor_gate.go` hold the decision turn that orders a flow source's state write before a later sink's read — keyed on the state ANCHOR (the validated `mcp.task_id` under `taskAnchoredState`, the session otherwise) rather than on the connection, so two sessions sharing a task share a turn. BOTH transports resolve that anchor through `enforcement.ResolveStateAnchor`, the same resolver the engine's own key builder uses, so the turn and the state key cannot disagree about a request (stdio's FIFO ticket queues are keyed on it too — it resolves to one anchor today, and keying it is what keeps that from being an assumption held up elsewhere). Whether a policy needs a turn at all is `config.LocalManifest.NeedsDecisionTurn`, called from both transports rather than spelled out at each and DERIVED from the state class each token declares (`capability.TokenStateAccumulation`) rather than from a list of token types; the engine's two skip gates are NOT the transport's business at all: it hands the ENGINE the tokens the policy carries (`config.LocalManifest.PolicyTokens` → `enforcement.WithPolicyTokens`), a fact, and the engine intersects them with its own handler registry. Both registries' keyed-with-refcount lifetime is ONE generic (`keyed_registry.go`: `keyedRegistry[T]` + the embedded `keyedEntry`), with the reclaim trigger supplied by the embedder — the gate drops at its last holder, the FIFO also waits for the tickets it handed out — so a leak or lock-ordering fix has one home rather than two. The stdio server-initiated leg's wait for the turn is BOUNDED (`samplingTurnWait`, as HTTP's is) and its ticket is abandonable — the turn skips a ticket whose waiter gave up. That bound is a `turnWait` PAIR rather than one duration: `perHolder` refuses a waiter only when the request actually HOLDING the turn has held it a whole window without handing off (so a waiter queued behind a moving queue is not refused, which is the property the inline version had for free and concurrent handlers lost), and `total` is the ceiling that keeps "the queue is moving" from meaning forever, since a parked waiter holds a `serverRequestPool` slot. That leg also runs on its OWN goroutine rather than inline on the upstream reader, on BOTH transports, through one shared `serverRequestPool` (`server_request_pool.go`: admission bounded at `maxConcurrentServerRequests`, refusing-plus-recording `RESOURCE_EXHAUSTED` on saturation, plus the teardown `drain`) scoped proxy-wide for stdio and PER SESSION for HTTP: the reader is the only goroutine that delivers upstream responses, so a handler parked on the turn used to stall every in-flight call for the length of the bound, repeatably (HTTP's blast radius is one session rather than the proxy, and under `taskAnchoredState` the turn holder can be a different session sharing the anchor). The cost is that server-initiated requests have NO ordering guarantee among themselves, and each transport's teardown drains them (`awaitServerRequestsDrained` / `releaseSessionState`) before releasing session state. A request reaches its turn through three tiers, every one of them addressed by the RESOLVED anchor rather than by a restatement of how the resolver decides, so all three are correct for any anchor kind rather than for the two that exist: the session's lock-free PIN (the gate for the anchor it resolved at registration, taken in `registerSession`, released by `releaseSessionState`), which serves every request on a session-anchored route and every request of a task-anchored session that stays on one task; the session's own `gateCache` (`session_gate_cache.go`) for the OTHER anchors it resolves, since a session that SPANS tasks — the shape task anchoring exists for — matched the pin on nothing after the move and took the route-wide registry round trip on every enforced call for the rest of its life; and the route registry itself, the always-correct path, reached by a non-serialized route (where it is a no-op) and by a request racing its own session's teardown, after the cache has stopped admitting. Reaching the cap is NOT an overflow into that tier: the cache sheds its least recently used entry and serves the request, so a session cycling wider than the cap pays the cache's bookkeeping on top of the registry round trip rather than a wrong turn (measured, `BenchmarkDecisionTurn_SpanThrashing` against `BenchmarkDecisionTurn_Registry`). The pin is deliberately never RE-pointed: it is read with no lock at all, so moving it means returning the registry reference that is the only thing stopping that gate being reclaimed and rebuilt under a request which read the old pointer and has not yet taken its turn — two gates for one anchor is not slow, it is unserialized. The cache carries the synchronization that hazard needs: a request taking a turn on a cached gate is COUNTED for the whole turn, so eviction (LRU, capped at `maxCachedSessionGates`, because the anchors are validated task claims and one connection must not pin one gate per task it ever touched) never drops a reference in use — an entry with users is RETIRED, removed from the map so nothing new joins it, its reference returned by whichever request leaves last, and `gateCache.close` does the same at teardown for anything that outlives the bounded in-flight drain. On a task-anchored route a session may SPAN anchors — each host request is decided, keyed and serialized on its own — and what pays for that is the leg with no request in scope: `httpSession.noteRequestAnchor` records the span and `spansAnchors` makes the server-initiated leg refuse for the session's life (`session_spans_anchors`), because that leg decides from the claims captured at `initialize` while the host leg decides from each request's, and two tokens differing only in `task_id` would otherwise taint one bucket and peek another; `initialize` routes through `dispatchRequest` too (its cross-cutting kill gate shared with the other locally-answered methods), with the per-transport response body supplied by an injected `buildInit` responder — only the HTTP *session-creating* `initialize` (no session/dispatchParams yet, and it carries the strict-audit gate) is answered outside the shared dispatcher. Gateway mode (top-level `transport: http` in config) multiplexes N upstreams on one `HTTPProxy`, each at `/mcp/<name>` with its own policy — per-route state lives in `route.go` (`UpstreamRoute`, built by `BuildRoutes`; its `routeSink` wraps the shared `*audit.Sink` and stamps the route name + policy version/digest), config parsing in `internal/config` (`GatewayConfig`; unknown YAML keys rejected; JSON Schema in `schemas/`). The package builds standalone on `internal/{audit,config,drift,mcp,pdp}` + `pkg/*`; the drift-check policy lives in `internal/drift`, and the transport imports it only for the `drift.CheckFunc` hook type (the binary injects `drift.MakeDriftCheck` as that hook, so the runtime calls the opaque hook and never references the comparison). Startup effects that overwrite SHARED last-writer-wins state (the control-token file, the session-kill TTL) run from each transport's own ready hook — `HTTPGatewayOptions.AfterListen` (post-bind) and `StdioProxyOptions.OnReady` (fired inside `Start` once the session is live) — never from the binary before the transport stands, so a proxy that fails to come up cannot clobber a running one. The exported seam the CLI consumes: `NewStdioProxy`/`StdioProxyOptions`, `NewHTTPProxyGateway`/`HTTPGatewayOptions`, `BuildRoutes`/`UpstreamRoute`/`LoadUpstreamPDP`/`LoadEffectReceiptVerifier`/`WrapRoutesWithJWT`/`AnyRouteAccumulatesSharedState`, the `Resolve*` flag resolvers, the control-token + OAuth-metadata helpers, `SetProxyVersion`, and the CLI-probe plumbing (`DoMCPHTTP`, `BuildUpstreamClient`, `BuildInitializeRequestWithID`, `ApplyInitializeResult`/`UpstreamHandshake`, `SessionHeader`, `IsInfraDenialCode`, `MaxUpstreamErrBodyBytes`). Protocol-revision negotiation lives in `revision.go`: the host side is established per context — pinned from the context's FIRST resolved message, by the goroutine that reads messages, NOT from the `initialize` response (that placement left the flip refusal inert for any peer on a revision with no handshake, and raced the reader for a pipelined follow-up) — and CHECKED per request against the `_meta` `io.modelcontextprotocol/protocolVersion` declaration, which is read by DECODING the params rather than scanning them for the key (JSON permits escaping any character of an object key, so a byte probe missed spellings the upstream reading the same forwarded bytes still saw) — omission inherits the context (and an unnegotiated context resolves to `capability.DefaultRevision`, the surface eunox already shipped, so nothing reaches a newer method set by leaving a declaration out), while a declaration that DISAGREES with its context is refused `UNSUPPORTED_PROTOCOL_VERSION` (-32022) rather than re-negotiated; the upstream side is pinned once per route/proxy from the handshake or the operator's `protocolVersion` key. The resolved revision travels on exactly ONE carrier — the context (`capability.WithProtocolRevision`, stamped by each transport's `negotiateHostRevision` and read back by `dispatch.go`'s `requestRevision`) — and the routing tables are derived from that same value the audit sink stamps `protocol_revision` from; it is deliberately NOT also a `dispatchParams` field, because two hand-threaded carriers had opposite zero-value semantics (the field defaulted, the context omitted) and an entry point that set one and forgot the other recorded "no revision decided" for a request it had decided under `2025-11-25`. The empty carrier is resolved to `capability.DefaultRevision` in `requestRevision` alone, so no two dispatch decisions can read it differently; the sink's omission is not a second reading of the same question — a pre-negotiation refusal has to be able to state that nothing was negotiated. The routing tables are DERIVED from `dispatch.go`'s `methodRegistry` — one declaration per method carrying the revisions it exists in (the `TokenSince` pattern), its request handler in one of two typed fields (`Decide` for a PDP-decided method, `Local` for a proxy-answered one, so "enforced but no handler" is unrepresentable), and its notification disposition in ONE `map[string]notificationDisposition` per revision whose zero value IS the fail-closed `notifyUnmapped` — so removal across revisions is expressed by ABSENCE (a method outside the peer's table hits `dispatchUnmapped` exactly as an unknown one does) and an entry declaring no revision fails the build. The fact "the handshake exists only in the older revision" is read off that registry too (`handshakeRevision`, exported as `HandshakeRevision()` for the CLI probe) rather than restated at each site that opens, answers, or version-stamps a handshake. The cross-cutting per-message gate ORDER — revision negotiation, then the swallowed set, then revocation, then fail-closed routing — is stated once in `dispatch.go`'s package comment and applied by `hostNotificationGate.admit` (the shared notification gate both transports call in place of the four checks each used to hand-place) and by `dispatchRequest`; negotiation runs first because a message whose revision is unresolved has no table to be looked up in, at the cost of one labelling exception (a revoked session's bad-version probe records as `UNSUPPORTED_PROTOCOL_VERSION`, not `KILL_SWITCH`) that `gate_order_test.go` asserts on both transports rather than leaving to prose.
- **PDP abstraction** — its own package `internal/pdp` (`pdp.go` + `jwt.go` + `redact.go`, the post-allow `redactFields` engine, which shares no state with the contract) defines `PolicyDecisionPoint`: Decide / DecideResourceRead / DecideResourceCancel / DecidePromptGet plus the embedded `ListFilterer` (list filtering) and `SamplingAuthorizer` (sampling) facets, folded into the one contract so every PDP implements them and the transports call them directly (no optional-interface type assertion). `DecideResourceCancel` is `resources/unsubscribe`'s own entry point, not a synonym for the read: a cancel is authorized by MATCH ALONE (kill check, constraint lookup, action check) and commits no session state, because metering it through the read decision let a spent `maxCalls` budget deny the unsubscribe that closes the stream the subscribe opened, and recorded a `sequenceBlock` antecedent plus `labelOutput` taint for a request that transfers nothing. Implementations: `ManifestPDP` (manifest via pkg/enforcement engine), `JWTPDP` (IdP capability claims; intersects with the manifest — JWT can only restrict, never expand. It also parses and asserts the two claim-borne narrowing surfaces at the TOKEN boundary — the `mcp.declassify` approvals and the RFC 8693 `act` + `mcp.delegation` chain — so a grant this build cannot enforce, or a chain whose hops widen, rejects the token rather than degrading silently on the decision path. The `mcp.capabilities` claim schema is experimental and the intersection is off by default, gated behind `--jwt-experimental-capabilities`/`JWTPDPOptions.ExperimentalCapabilities`; with it off, a token carrying `mcp.capabilities` is rejected at validation, fail closed. JWT signature/exp/iss/aud verification and identity claims stay always-active), `AlwaysAllowPDP` (audit/wiretap mode). `surface_pin.go` holds Tier-2 interface pinning (`SurfaceBaseline`): the advertised-surface hash of every tool a session sees, auto-baselined at the session-start probe and re-diffed on every `tools/list`, with a changed surface a sticky PER-SESSION break the call leg hard-denies and the list filter hides. It also holds the two context seams the `(ctx, result)`-shaped `ListFilterer`/`RecordObservedToolHashes` methods need — `WithSessionID` (Tier-2's per-session key) and `WithDeclaredLabels` (the attribution interface's per-call flow labels, union-only at the sink). The package builds standalone on `pkg/*` — no `internal/audit` dependency (the caller-identity adapter the sink's `WithIdentity` seam takes is the binary's, built over the exported `JWTClaimsPtr`; `audit.Identity`'s fields stay named rather than five positional values either way) and no `internal/mcp` dependency (the `sampling/createMessage` method name it consults lives in `pkg/capability.MethodSamplingCreateMessage`, reachable from every layer including `internal/audit`); the binary wires concrete PDPs into the transports via the exported contract. The contract also carries the two questions a COMPOSING layer asks about the deciding PDP's condition semantics: `EvaluateClaimCondition` (evaluate one claim-derived condition under this PDP's own handlers, committing nothing) and `ConditionHandlerOverridden` (is this type's handler an embedder's replacement?) — the second for the one claim-side arm that cannot dispatch through an override at all, `allowedOperations`, whose `op=` shorthand names no argument and therefore scans every one while the engine's handler hard-denies exactly that empty argument; that divergence is refused (at startup in `WrapRoutesWithJWT`, and at the request as the backstop) rather than resolved. Every PDP must decide every method explicitly — no silent fall-through to "forward verbatim".
- **Audit** — its own package `internal/audit` (`audit.go` writer core — including the `Identity` the caller-injected `WithIdentity` extractor returns, which carries the acting `delegate` + `delegation_depth` beside agent/task/user so a delegated ALLOW is attributable to the sub-agent that made it and not only to the human it acts for, `keys.go` HMAC key resolution/load/create + key-file mode tightening, `resume.go` startup tail read + partial-tail recovery, `rotate.go` size-triggered rotation + retention pruning, `verify.go` per-record HMAC + tamper-evident chain verification), consumed by the binary through the exported `audit.Sink` (`RecordAllow`/`RecordDeny`/`Close`/`VerifyLog`). The recorders are non-blocking (struct init + channel send); serialization, HMAC signing, and disk I/O happen in a single background drainer goroutine. The package builds standalone — it depends only on `internal/config` (the shared `ExpandHome` helper plus the file-substitution guards `RefuseNonRegularPath`, `OpenNoFollow` and `OpenNonBlock`), `pkg/capability`, and the stdlib, never back on the binary. In gateway mode, `routeSink` (in `internal/transport`) wraps the shared `*audit.Sink` and stamps each record with the route name, `policy_version`, and `policy_sha256` — it calls the gateway-aware `Sink.Record(ctx, audit.RecordParams{…})` directly, whose fields are named rather than positional so a transposition cannot silently swap two structured audit fields.
- **Config** — its own package `internal/config` (`manifest.go` `LocalManifest` load/validate/merge, `gateway_config.go` `GatewayConfig` parse/validate + env-ref expansion, `schema_version.go` grammar-version negotiation (the parseable set and the token-inheritance order are ONE ordered list, derived from `capability.PublishedSchemaVersions`; `revisionAdmits` indexes it, so a token is admitted by the revision that introduced it and every revision published after — publishing a revision is a data append, not a rewritten boolean), `resolve.go` shared `ResolveBool`/`MaxDurationMs`/`ExpandHome` helpers, `manifest_policy.go` the `(*LocalManifest)` policy-property methods `AccumulatesSharedState`/`NeedsDecisionTurn`/`PolicyTokens`/`AuditOnlyCount`/`Digest` (the first two derived from the tokens' declared state classes, not from a list of token types; `PolicyTokens` is deliberately a FACT — which discriminators the policy carries — for the engine to draw its own conclusions from). Environment-reference expansion is per-FIELD (`envGrammar` + the `env` struct tag): full `$VAR`/`${VAR}` by default, braced-only for a stdio upstream's `command`/`args`, and full-in-the-authority/braced-only-in-the-query for `upstreamUrl`, with the unset-reference GUARD reading the same declaration so the two cannot disagree about what a `$` means in a given field, `nofollow_{unix,other}.go` the build-tagged `OpenNoFollow` `O_NOFOLLOW` and `OpenNonBlock` `O_NONBLOCK` flags plus `RefuseNonRegularPath`). It holds the binary's config + manifest *loading* layer and builds standalone — depends only on `pkg/*`, `gopkg.in/yaml.v3`, and the stdlib, never back on the binary — so the CLI subcommands, `internal/audit` (`ExpandHome`, `OpenNoFollow`, `OpenNonBlock`, `RefuseNonRegularPath`), and the transport layer import the config/manifest types from a non-main home. Exported seam: `LocalManifest`/`LoadManifest`/`MergeManifests`, `GatewayConfig`/`UpstreamConfig`/`RouteDefaults`/`LoadGatewayConfig`, `ExpandHome`, `EffectUnannotatedTargets`, and the consumed `(*GatewayConfig).Validate`/`HostTransport`/`AuditModeFor`/`NoPolicyStartupRejection`/`ResolvedTaskAnchoredState` plus `HostTransportHTTP`/`HostTransportStdio`; the validators (`validateLocalManifest`, …) stay unexported.
- **Drift** — its own package `internal/drift` (`drift.go`: the startup manifest-drift-comparison policy, FM-1 through FM-6). `CheckManifestDrift` compares the live upstream tool list + server version against the manifest and returns `Warning`s; `MakeDriftCheck` builds the session-start `CheckFunc` hook the transports run (fatal-or-skip on a probe failure depending on whether the manifest pins descriptionHash); `ParseToolsListResult` decodes the probed `tools/list` into `[]UpstreamTool`; `BestManifestConstraint` backs the `validate --live` COVERED report. The `CheckFunc` type moved here from `internal/transport`. The package builds standalone on `internal/{config,mcp,pdp}` + `pkg/{capability,enforcement}` (never `internal/transport`, which imports it — so no cycle), and is imported by the binary (`drift.MakeDriftCheck` wired into `transport.BuildRoutes`, `validate --live`, the live-upstream probe) and by `internal/transport` (the `CheckFunc` field on the proxy/route + the `BuildRoutes` hook-factory param).
- **Subcommands** — proxy, validate (`--live` diffs manifest against a running upstream; also reports effect-contract coverage and names the unannotated capabilities), init (deny-all starter manifest from live tool list), suggest (proposes manifest tightenings from the audit log), kill, audit-verify, stats, contracts (verifies a local effect-contract corpus, prints an entry's `effect.ref` pin, and — with `--trust-keys` — verifies its signed attestations against a local trust store; `--attest-payload` prints the bytes a publisher signs, since eunox verifies attestations and never mints them. Offline throughout: neither the registry nor any key is fetched), doctor, version. Each lives in its own file (`kill.go`, `audit_verify.go`, `stats.go`, `contracts.go`, `doctor.go`, …); `main.go` holds the dispatch plus the security-critical proxy wiring.

### pkg/

- **`pkg/capability`** — manifest/constraint/condition types, validation, directives (e.g. `redactFields`), JWKS fetching and JWT verification. `revision.go` holds the MCP protocol-revision vocabulary (`Revision`, `PublishedRevisions`, `ParseRevision`, `DefaultRevision`, the `_meta` key, and the context carrier the audit tape's `protocol_revision` field reads) — here rather than in `internal/mcp` because `internal/config` (which parses the operator's pin) and `internal/audit` (which stamps the decided revision) both need it and neither may import that package, the same reason the method-name constants live here. Condition types are string-discriminated (`allowedValues`, `maxCalls`, `timeWindow`, …; authoritative list in `pkg/capability/condition.go`). `flowlabel.go` holds the information-flow tokens; `effect.go` holds the effect layer (the closed reversibility vocabulary, `EffectContract` + `ResolveEffect`, the `effectClass`/`blastRadius` conditions, the top-level `EffectCeiling`, and `EffectContractDigest` — the content digest a manifest's `effect.ref` pins and the loader verifies LOCALLY, so no registry fetch is on the decision path); `attribution.go` holds the `io.eunolabs.context-manifest` `_meta` interface; `receipt.go` holds the effect-receipt surface (the `io.eunolabs.effect-receipt` result-`_meta` block, its signature verification against an upstream's OWN key domain — never the caller-authenticating JWKS — and the consistency check against the contract the decision used; post-hoc and evidential only, and entirely inert unless an operator configures `effectReceiptKeys` for that upstream). `declassify.go` holds the declassification surface (the `declassify` directive and the `DeclassifyApproval` grant carried on the `mcp.declassify` claim of an already-verified token — the ONLY token that removes a flow label, hence approval-gated and fail-closed to `escalate`; a grant marked `once` is single-use, burned by its mandatory `id` in the engine's anchored ledger), and `declassify_commit.go` the `Declassification` commit handle the decision mints and the second phase consumes — opaque, single-use, carrying its authorized set unexported, so the phase that APPLIES a clear cannot widen what the phase that AUTHORIZED it resolved; `delegation.go` holds delegation attenuation (the RFC 8693 `act` actor chain plus the per-hop `mcp.delegation` grants, and `ValidateDelegationChain`, which REJECTS a token whose hops widen rather than clamping it — every axis narrows in a fixed direction, so consuming the claims needs no experimental gate); `taskvar.go` holds the closed `${task.*}` variable set; `grammar.go` holds the published grammar revisions and `TokenSince`, the one classification lookup — each prototype registry entry declares the revision that introduced it, and `internal/config`'s loader gate reads it rather than keeping tables of its own; `tokenstate.go` holds the second thing every entry declares, `State` — the cross-call state the token's enforcement touches (`StateNone`, `StateAtomic` for a budget admitted through one atomic `AdmitAll`, `StateNonAtomic` for a non-atomic read-then-write) — read through `TokenStateAccumulation`/`ConditionStateAccumulation`/`DirectiveStateAccumulation`, from which both the decision turn's predicate and the multi-instance shared-state advisory are derived; `subsystem.go` holds the third, `Uses` — which OPTIONAL engine facility that enforcement reads (`SubsystemNone`, `SubsystemAntecedentHistory`, `SubsystemFlowLabels`) — read through `TokenUsesEngineSubsystem` and `DeclarationUsesSubsystem` (the one place the unclassified-means-everything rule lives, shared with the handler-side declaration). The engine's two skip gates derive from it, but through the HANDLER REGISTRY rather than through the manifest: the declaration describes the handler this build ships, and `enforcement.WithConditionHandler`/`WithCommittingConditionHandler` can replace any token's handler, so an override that reads the flow store while the token it replaced declares nothing would otherwise have that path skipped out from under it (an override is unclassified unless it implements `enforcement.SubsystemDependent`). All of these are PUBLISHED in `schemaVersion "0.2"` (the batched bump; the `"0.2-draft"` staging string is removed, not aliased) and are NOT part of `0.1` — a `0.1` manifest using one is refused at load. They are documented in `docs/capability-manifest-guide.md` §§5b-5c, `docs/effect-contracts.md`, and `docs/attribution-interface.md`, and mirrored into `schemas/eunox-capability-manifest.schema.json`. The effect-RECEIPT surface in `receipt.go` is the one piece with no manifest token at all: it is gated by an operator explicitly configuring `effectReceiptKeys` for an upstream, a stronger opt-in than a schemaVersion, so it ships enabled-when-configured under either grammar.
- **`pkg/enforcement`** — the decision engine. Conditions are evaluated through a handler registry on `Engine`, whose entries carry a subsystem declaration alongside the handler (`registeredHandler`): a built-in takes it from the token's `pkg/capability` prototype entry, an override from `SubsystemDependent` if it implements it and is UNCLASSIFIED otherwise. An entry holds ONE of two shapes, never both — a pure `ConditionHandler` (`WithConditionHandler`) or a quota-consuming `CommittingConditionHandler` (`WithCommittingConditionHandler`), the latter carrying `PrepareCommit` alone and no `Handle`, so a committing condition has one entry point by construction rather than a second implementation the engine never calls. Its skip/commit contract is asserted in BOTH directions at the one site that consumes a `PrepareCommit` result (`commitDeferredConditions`), and both violations hard-deny: a skip the context did not authorize would leave the rest of the deferred set unchecked, and a bucket derived under `SkipQuota` would spend real budget on an `--audit` route whose whole contract is that none is consumed. Those two assertions make the set uniform by construction, which is why there is no post-loop partial-skip guard to keep in agreement with them. `New` derives the two skip gates from that registry, intersected with the tokens the caller declares its policy carries (`WithPolicyTokens` — a fact about the policy; the retired `WithoutAntecedentRecording`/`WithoutFlowLabels` asked a caller for the conclusion, which a manifest-side derivation could get wrong for a replaced handler). The two extension points (`policy`, `custom`) answer from the wired `PolicyEvaluator` when it declares, rather than conservatively; pluggable `Clock`, `CallCounter`, `FlowLabelStore`, `EffectCeiling`, and `PolicyEvaluator` (external PDPs like OPA/Cedar) via functional options. `flowlabel.go` and `effect.go` hold the two axes' handlers; `delegation.go` holds the decision-path half of delegation attenuation (the target gate, the effect-class cap, and the redaction/allow-label composition), and `anchor.go` owns the ANCHOR every piece of accumulated state is keyed on — exported as `StateAnchor`/`ResolveStateAnchor`/`AnchorKind`, because a transport serializing decisions has to key its turn on the same subject the state accrues to and a second reading of "is this task-anchored" is where the two silently diverge (the two ENCODINGS differ on purpose: the engine's counter/store key keeps its session form byte-compatible with pre-anchoring deployments, `StateAnchor.Key()` is the in-process turn-registry key) — the session by default, or the validated `mcp.task_id` claim under `WithTaskAnchoredState` (opt-in; falls back to the session only for a request carrying NO token, refuses an authenticated one whose token carries no `task_id` rather than splitting its state across two buckets, and never shares state on the strength of something the caller did not prove). Every key builder routes through `Engine.anchoredKey`, so a new piece of accumulated state cannot be added under session keying while every existing one follows the task. The `effectCeiling` is NOT a condition: it runs once on the allow tail, after the matched constraint's conditions and BEFORE the session-state commit, so an over-ceiling call leaves neither a phantom `sequenceBlock` antecedent nor a stranded flow label. Both effect conditions and the ceiling read ONE `ResolveEffect` of the matched constraint's contract, threaded through the context, so they cannot disagree about what the call's effect was.
- **`pkg/callcounter`**, **`pkg/killswitch`** — in-memory and Redis backends behind a common interface (Redis enables multi-instance deployments; tests use miniredis). Redis CLUSTER is unsupported and refused rather than documented: `callcounter.NewRedis` returns an error for a `*redis.ClusterClient`/`*redis.Ring` (the library spelling) and the binary refuses a `--redis-addr` pointed at a cluster node after its startup ping (the operator spelling), because `AdmitAll`'s multi-key `EVAL` is otherwise refused with `CROSSSLOT` at the first policy carrying two quota buckets — fail-closed, so invisible until then. `killswitch`'s per-master SCAN stays for a consumer wiring that backend alone. `killswitch.Manager` carries `HealthStatus` — the readiness question asked with no request in hand, on the seam so a consumer holding the interface can distinguish "not ready" from "backend down" without matching backend-specific sentinels — and the confirmability rule (a backend that cannot confirm its kill set reports the cause from EVERY reader rather than serving a silent all-clear) is stated once on the interface and checked by a cross-backend conformance table. `InMemory`'s zero value is usable: the kill sets are created on first write, where they used to panic. It also carries `ObserveRevocations`: a kill has two effects and only one of them is a read, so a consumer learning of one through `ShouldBlock` alone can DENY the traffic but reclaim nothing the revoked session holds. Both backends notify (Redis from its pub/sub listener AND its reconcile commit, so a dropped publish still reclaims), the callback must not block, and the `Revocation` is a trigger rather than a work list — the HTTP transport responds by re-asking about the sessions it holds. Every quota admission goes through ONE primitive, `AdmitAll(ctx, []capability.QuotaBucket)`, which admits a whole batch of buckets atomically or none of them. A bucket's `Counted` flag picks its accounting: entry-counting (backing `maxCalls`) or weight-summing (backing `blastRadius`'s cumulative `maxTotal`/`windowSeconds` bound). The two exist for COST, not expressiveness — a count is O(1) in both backends while a weighted total is summed per entry — and a single batch may mix them, so a capability carrying `maxCalls` alongside a cumulative `blastRadius` commits both in one call. What the manifest loader refuses is two buckets of the same kind on the same window (they would share one physical key); `checkDistinctBuckets` is the counter's own runtime backstop for the same shape. A lone `maxCalls` or a lone cumulative `blastRadius` commits through the same primitive as a one-element batch: there is no single-bucket method to drift from it.
- **`pkg/circuitbreaker`** — generic circuit breaker; the only production wiring today guards JWKS endpoint fetches (not upstream MCP calls, which rely on per-call timeouts).

## Load-bearing invariants (from CONTRIBUTING.md)

- **Fail closed.** On any ambiguity — missing manifest, unmapped method, malformed JWT, unset condition argument — deny, with a structured error code (`AUTHORIZATION_FAILED`, `CONDITION_FAILED`, …), and log it. New code paths must preserve this.
- **Audit records are append-only and structured.** Never rewrite a record, never put free-form text in a structured field, never add a top-level field without updating the threat model (`docs/threat-model-mcp.md`).
- **No telemetry / background network activity** without explicit design discussion.
- **Pre-1.0: no backwards-compatibility shims.** Change manifest grammar, audit shape, or config keys cleanly and document the migration. Don't flag back-compat breaks as problems.
- **One static binary on purpose** — new runtime dependencies need strong justification.
- **No emojis in source files or code comments** (README/site are fine).
- Conditions match a specific argument name; never silently match alternatives.

## Conventions

- Every `.go` file starts with the two-line header: `// Copyright 2026 Eunolabs, LLC` + `// SPDX-License-Identifier: Apache-2.0`.
- **Comments explain WHY or HOW, never WHAT.** Delete a comment that just restates the line below it in words — if the code already says it, the comment is noise. Keep or write a comment only for the reason/tradeoff/constraint/bug behind a choice (WHY) or a non-obvious algorithm/ordering/concurrency requirement (HOW); cap it at one or two lines, no preamble, don't restate identifier names. Exported (capitalized) top-level `func`/`type`/`const`/`var` still need a godoc comment starting with their own name (`revive`'s `exported` lint rule requires it) even when there's no WHY/HOW to add — keep that lead-in minimal rather than padding it with restatement. If a comment asserts a rationale you can't verify against the surrounding code, mark it `// TODO: confirm rationale` instead of inventing one. License headers, TODO/FIXME with context, spec/issue links, and security warnings are always kept regardless of this rule.
- Conventional Commits (`feat:`, `fix:`, `sec:`, `perf:`, `refactor:`, `docs:`, `test:`, `ci:`, `chore:`; `!` for breaking). `refactor:` means no behavior change — a restructuring that also fixes observable behavior is a `fix:`. DCO sign-off required: `git commit -s`.
- Tests: new condition types need table-driven tests under `pkg/capability/` (allow + deny + malformed-input cases); new MCP method coverage needs a test in `internal/transport/enforcement_gaps_test.go` — including its PER-REVISION cells (which peer's revision dispatches it, which denies it fail-closed), since revision membership is declared on the method itself; only the table-DERIVATION machinery lives in `internal/transport/dispatch_revision_test.go`, the negotiation rule in `revision_test.go`, and the per-message gate order in `gate_order_test.go`; new audit-record fields need a sign-and-verify round-trip test; changing the duplicate-key scan in `internal/pdp` means keeping it in agreement with the tokenizer oracle in `scan_oracle_test.go` (equivalence table + fuzz targets, and a real fuzz campaign, not just the seeds).
- Every condition/directive discriminator declares THREE things on its `pkg/capability` prototype registry entry: the revision that introduced it (`Since`), the cross-call state its enforcement touches (`State`; see `tokenstate.go` for the rule, and note that an atomic `AdmitAll` budget accumulates but needs no decision turn), and the optional engine subsystems that enforcement reads (`Uses`; see `subsystem.go` — `SubsystemNone`, `SubsystemAntecedentHistory`, `SubsystemFlowLabels`, with the two extension-point tokens declaring everything because what an embedder's evaluator reads is not knowable here). An entry missing any of them fails the build (`TestTokenSince_…`/`TestTokenStateAccumulation_EveryRegisteredTokenDeclaresAClass`/`TestTokenEngineSubsystems_EveryRegisteredTokenDeclaresOne`) and is treated as the strongest class — and as depending on every subsystem — meanwhile. `internal/config`'s `checkTokenRevision` reads `Since` through `capability.TokenSince`, and a token with no `Since` is refused under every revision. A non-discriminator token (`effectCeiling`, a `${task.*}` value) has no registry entry and is gated inside `checkTokenGrammarVersion` instead. Either way it needs a test asserting it is REFUSED under `0.1` — that one gate is what keeps a later revision's predicate from silently widening an earlier one.
- Adding a condition or directive type also means adding a branch to `schemas/eunox-capability-manifest.schema.json`; `cmd/eunox`'s schema drift tests derive their expectation from the condition prototype registry, so a missing branch fails the build rather than shipping an undocumented token.
- Editing a `registry/contracts/` entry means recomputing its `digest`; `go test ./internal/registry/` fails otherwise, and so does any manifest that pinned the old value via `effect.ref`.
- Behavior changes need a docs update in the same PR. Manifest grammar changes also update `docs/capability-manifest-guide.md` and the spec repo (`eunolabs/agent-capability-manifest`). Schema changes update `schemas/` plus a roundtrip test.
- Security vulnerabilities go through `SECURITY.md`, not public issues.
- Never reference issue numbers, bug IDs, or internal milestones (stages, phases, epics, sprints) in code comments, documentation, or site copy. Those references rot and belong in the PR description or commit message only.
