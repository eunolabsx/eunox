# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`eunox` is a policy-enforcement proxy for MCP servers (Go, one static binary). It sits between an MCP host and an upstream MCP server, checks every enforced MCP method (`tools/call`, `resources/read`, `resources/subscribe`, `resources/unsubscribe`, `prompts/get`, `sampling/createMessage`) against a YAML capability manifest before forwarding, filters `*/list` responses to permitted entries, and writes every decision to an HMAC-SHA256-signed OCSF JSONL audit log.

## Commands

```bash
make build           # → bin/eunox
make test            # go test -race -count=1 ./...
make lint            # go vet + golangci-lint at CI's pinned version (installs it when PATH has another)
make fmt             # gofmt -w every .go file
make check-fmt       # gofmt-clean check on every .go file (CI-enforced); fix with `make fmt`
make check-license   # Apache-2.0 SPDX header on every .go file (CI-enforced)
make check-notice    # NOTICE lists exactly the binary's third-party modules (CI-enforced)
make coverage        # coverage.out for all packages — CI gates pkg/, internal/ and cmd/ at 80% each
```

Run a single test (standard Go tooling):

```bash
go test -race -count=1 -run 'TestName' ./cmd/eunox/
```

End-to-end demo stack (Docker) — the fastest way to verify a behavior change against a real proxy + mock upstream: `make -C demo up`, then `make -C demo allow|deny|audit`; gateway variant `make -C demo gateway-up`.

## Architecture

Three layers: `cmd/eunox/` is the binary (CLI, transport wiring, PDP wiring); `pkg/` holds the importable engine and supporting libraries; and `internal/` holds subsystems factored out of the binary behind narrow seams — `internal/audit` (the tamper-evident audit log, consumed through the exported `audit.Sink`), `internal/mcp` (the MCP protocol message types plus the JSON-RPC envelope/newline-framing/classification layer — `RPCMsg`, `MsgReader`/`MsgWriter`, `MsgKey`, the response builders — shared by the transports, PDPs, and the CLI's live-upstream probe), `internal/pdp` (the policy decision points: the `PolicyDecisionPoint` contract and the `ManifestPDP`/`JWTPDP`/`AlwaysAllowPDP` implementations), `internal/config` (the config + manifest loading layer: `GatewayConfig` parsing, `LocalManifest` load/validate/merge, schema-version negotiation), `internal/drift` (the startup manifest-drift-comparison policy: `CheckManifestDrift`/`MakeDriftCheck`/`UpstreamTool`/`Warning`/`ParseToolsListResult`/`CheckFunc`, shared by the binary's `validate --live` and the transport runtime), `internal/registry` (the effect-contract corpus format — `Contract`/`LoadCorpus`/`Validate` — plus the attestation trust layer in `attest.go` — `Signature`/`TrustStore`/`LoadTrustStore`/`VerifyAttestations`/`AttestationPayload` — over the shipped corpus in `registry/contracts/`; authoring-time input only, never consulted on the decision path, and no key is ever fetched. Both documents it reads are REVIEWED before they are decoded, which is the whole trust story here, so `strictDecodeJSON` refuses an ambiguous member name before the decode resolves it (`capability.RefuseAmbiguousJSONKeys`, the whole-document form of the fold the claim decoders apply to one object — `DisallowUnknownFields` cannot see a second SPELLING of a known field, and the digest is computed over what was decoded, so a case-variant `"Effect"` block self-validates while a reviewer reads the one above it; `NewEffectReceiptVerifier` takes the same scan over the JWKS an operator configures per upstream). `checkPinnableNumbers` is the other half of "an entry is what a reviewer read": this loader keeps a number's literal and the manifest loader renormalizes it, so a `blastRadius` value whose spelling does not survive that is refused at PUBLISH — it would otherwise ship self-validating and impossible to pin, surfacing later as a false tampering report against an author who copied the block verbatim. The renormalization is `internal/config`'s, so the answer about what survives it is asked there (`config.CanonicalNumberLiteral`) rather than reimplemented), `internal/redisutil` (the go-redis TOPOLOGY question both Redis backends ask — `ShardFanOut`/`Topology`/`ClassifyTopology`/`Resolution`/`Reconcile`/`Reconciliation`/`IsNilClient`/`ErrIncompleteFanOut`, where the fan-out it hands back is required to be COMPLETE and go-redis' Ring iterator is not (it skips a shard voted down and returns nil), so the Ring arm is wrapped with the check that turns a partial pass into an error, exported as `WholeRingFanOut` because a consumer whose ring sits behind a decorator can only DECLARE an iterator and the unchecked one is all they otherwise have — hosted below `pkg/callcounter` and `pkg/killswitch` rather than inside either, since a kill-switch-only consumer otherwise linked the whole counter package for a type switch and the next topology question would be answered in a package with no reason to know a keyless SCAN exists), and `internal/transport` (the stdio + HTTP/gateway transport runtime — the proxies, the shared dispatch/forward/enforcement core, the remote-upstream bridge, the route wiring, and the control-token/OAuth-metadata/health endpoints; the binary just wires it). The layering is `internal/mcp` ← `internal/pdp` ← `internal/transport` ← the binary, with `internal/audit` below the transport but deliberately NOT below the PDP layer (the caller-identity adapter that joins the two — validated claims to the `audit.Identity` a record stamps — lives in the binary, `cmd/eunox/audit_identity.go`, which is the one place that already imports both; having `internal/pdp` return the writer's own struct satisfied the `WithIdentity` seam by inverting its arrow rather than removing it, and made every consumer of the PDP layer link the audit writer), and with `internal/config` and `internal/drift` sibling lower layers (`internal/drift` builds on `internal/{config,mcp,pdp}` + `pkg/{capability,enforcement}`) imported by both the CLI and the transport layer; `internal/transport` builds standalone on `internal/{audit,config,drift,mcp,pdp}` + `pkg/*` with zero references back into the binary. `internal/redisutil` is the one arrow that runs the other way — `pkg/{callcounter,killswitch}` import it — and the only `internal/` package that is not factored out of the BINARY: it is factored out of two `pkg/` libraries that both need the same go-redis answer, and it sits in `internal/` rather than `pkg/redisx` because nothing outside the module needs it and the complaint that moved it was precisely that a topology type switch had become published API for the benefit of a consumer that was not itself. It depends on go-redis and the stdlib alone, so it adds no cycle and no reachable API surface.

**Request flow:** host JSON-RPC request → transport layer parses method + arguments → `PolicyDecisionPoint.Decide(...)` → allow: forward to upstream; deny: structured JSON-RPC error back to host (upstream never called) → either way, an audit record is written.

### cmd/eunox

- **Transports** — their own package `internal/transport`; the binary just constructs the proxies (`transport.NewStdioProxy`/`transport.NewHTTPProxyGateway`) and calls `.Start`/`.Serve`. Both constructors first run `wiring.go`'s `requireUsableOptions`, which panics naming any options field holding a TYPED nil: `opts.X == nil` compares the interface, so a wired-but-nil subsystem walked through the absent-case substitution and panicked inside a dependency's goroutine instead. Reflective over the struct rather than a branch per subsystem (a hand-listed guard leaves the next interface field unchecked) and therefore reaching interface-typed fields alone, which is what keeps a legitimately absent `*audit.Sink` constructing; it DESCENDS into everything that can hold an interface BY VALUE — struct-kind fields, so a nested options block cannot inherit "unchecked" (the shape a depth-1 walk stopped covering while the test asserting its coverage stopped asserting on it), and the ELEMENTS of a map, slice or array, so a container of interfaces cannot either (the same failure one dimension out, and the one two hand-written lines at a single construction site do not generalize past) — terminating with no visited set on the struct half (Go forbids a struct containing itself by value) and WITH one on the container half (a container value can close a cycle its type permits, and a hung constructor is a worse diagnosis than the dereference this guard replaces), and stops at a POINTER, since a pointer field is a subsystem the caller built and its internals are its own package's business; that stop is on the pointer rather than on the container holding it, which is what leaves the map (`Routes`, whose elements are pointers) closed at its own construction site where `NewHTTPProxyGateway` refuses a nil route AND the one interface a route holds — a residual now held to a declaration (`containersClosedAtTheirSeam`) so a SECOND pointer-element container option fails the build rather than inheriting those two lines silently; a field reflect will not let it READ (anything reachable only through an unexported name, the read-only flag being propagated to exported fields under it) is SKIPPED rather than refused, since a field no outside caller can set is not the caller-supplied wiring this guard is about — refusing it fired on valid wiring while naming a field that was already exported; substituting a working default is refused for the kill switch in particular, since revocation would silently stop crossing replicas. The subsystems handed over as PARAMETERS rather than options fields (`BuildRoutes`/`LoadUpstreamPDP`'s counter, flow store and kill switch — the three the stdio transport reaches through the second of those alone, since `StdioProxyOptions` carries none of them) take the same refusal through `requireUsable`, named one by one because a parameter list is complete by compilation where a struct field is not. The nilness question itself is NOT this package's: it delegates to `capability.IsNilValue` (`healthSnapshot.fold` and the server-initiated leg's sink ask it too, and `fold` answers a wired-but-nil subsystem DEGRADED, the backstop for anything this package did not construct). The local kind switch beside it is gone — the dependency-weight argument that licenses `internal/redisutil`'s separate copy does not apply to a package that already links `pkg/capability` in dozens of files, and the copy's kind list had drifted WIDER than the shared one, which is the direction that hides a divergence until the first func- or map-typed subsystem. `stdio.go` (`StdioProxy`: host on stdin/stdout, one upstream as subprocess or remote HTTP via `stdio_http_upstream.go`); the `http*.go` files (`HTTPProxy`: MCP Streamable HTTP/SSE, one upstream subprocess per client session, `Mcp-Session-Id` header, loopback-only `/control/kill`) — split by concern into `http.go` (server core: construction + `Serve`), `http_routing.go` (`/mcp` POST/GET/DELETE + `/control/kill`), `http_security.go` (auth, Origin/DNS-rebinding, source-IP, loopback), `http_session.go` (`httpSession` lifecycle, registry, idle reaper, upstream I/O, SSE broadcast; `establishSession` is the ONE tail both session-creating arms run — the pre-spawn slot RESERVATION and its one-owner release, the start budget (`sessionStartBudget`) and the write-deadline re-arm covering it, the establishment context, the pre-creation `clientIP` capture, and the remote/local spawn — since the two copies were hand-mirrored down to a citation of each other and differed only in the SEED, while `gate_order_test.go` pins their order from another file, so a fix landing on one arm was invisible to every test that reads the other; each arm keeps its OWN gates above that tail, and the four primitives are held to the single caller by a source guard. The reservation is released when ESTABLISHMENT ends rather than when the caller is done, since `registerSession` has published the session by then and the cap counts registered sessions too; killed-session reclaim runs on the kill's own DELIVERY — `killswitch.Manager.ObserveRevocations` wakes `reclaimOnRevocation`, which re-asks the kill switch about each held session — with the idle reaper's killed arm as the backstop it cannot be, since that reaper does not run at all under `sessionIdleTimeoutMs: 0`), and `http_handlers.go` (upstream-timeout/denial helpers + server-initiated request handling); `record_limiter.go` holds the admission control over the audit records a REFUSAL writes, and `notice.go` the stderr line beside it. The two are bounded SEPARATELY and for different reasons: a leg can meter no record it writes (an established session's kill records are the tape an emergency stop depends on) and still owe a bound on a per-frame syscall. Both are built on one `recordRateLimiter` token bucket, which rolls a suppressed write into the next admitted one rather than losing it.

The RECORD half is keyed by refusal CATEGORY: a shared bucket let a spray of cheap unauthenticated Origin probes absorb the whole budget and suppress a concurrent control-token brute force into a number on somebody else's record. Categories are declared in ONE list (`allRefusalCategories`) from which the metered set is derived, with `exemptRefusals` naming the two that write unmetered — the fail-closed routing refusal and the enforced-method-as-notification reject, both reachable only by a peer whose other traffic writes policy DENY records at the same one-per-message cost, and a policy verdict may never be admission-controlled. That exemption is scoped to the RECORD: a stderr line is not a verdict, so the routing refusal's own notice is bounded on the notice bucket. The declaration is applied by the ONE admission both spellings of a refusal write go through (`categoryRecordLimiter.admitRefusal`) rather than at each entry point, since an exempt category holds no bucket and reading the exemption only at the recorder-resolving spelling left the other one falling to the floor-rate fallback — throttling an exempt refusal HARDER than a metered one, the inversion of what the declaration says. A leg RESOLVES its recorder per category through `refusalRecorders.forCategory` (the ONE resolver, reached by both framings of the routing refusal), which reads that declaration — an UNDECLARED category resolving METERED, the bounded direction — rather than holding one recorder for every refusal it can take: a leg's arms disagree, so one per-leg thunk handed an exempt refusal the metered recorder and spent a `catKill` token anyway. `refusalLimits` holds the record buckets APART from the sink every params struct already carries (a second copy of that sink is a wiring fault nothing would catch), and `limits` is a NAMED field rather than an embedded one, since embedding promoted `recorders` onto the resolved pair and let a producer mint one keeping this leg's buckets while pointing at a different tape. Each transport builds buckets for the categories it charges (`stdioRefusalCategories`) rather than the whole table. Routes hold NO part of either budget — the notice table is the proxy's one table and a session's refusals charge the proxy-wide category table — so a `Routes` map may legitimately be shared by two proxies and the bind check that refused that is gone with the per-route state it protected; the HTTP legs resolve their channel through one `noticeWriter()` with no route or session parameter, since neither selects anything.

The NOTICE half is keyed by CLASS — `classTraffic` (an account of what a peer or upstream SENT), `classFailure` (an account of something that BROKE in transit) and `classObligation` (a security obligation that did not hold: a `redactFields` directive that could not be applied, a clear that did not commit, a signed receipt contradicting its contract) — so a flood of the cheapest peer-driven line cannot take the last token from the line that says an upstream is down, and an upstream flooding the errors it can produce at will cannot take it from the line that says one of its obligations failed. What the third class does not buy is stated on the type: a downed flow store or a stale `effect.ref` drives it at the request rate from a conforming peer, so within the class one obligation's failure can still elide another's. `noticeWriter.admitNotice` is the ONE entry point and every metered site takes it BEFORE building its arguments, which are the expensive part of a suppressed line — a bounded method name, a sanitized target, a joined reason list, each escaping to the heap per frame on the flood path the bucket exists for; it hands back a `noticeLine` rather than the bool that shape was first proposed as, since a bool is a peek the mechanism never hears about again and a site pre-gating on one would either spend a second token or skip without counting, which under-states the flood the count exists to report. A site with no entry in `noticeSiteClass` charges a floor-rate fallback rather than writing free. `noticeLatch` is the one-shot for a line whose first occurrence is the whole finding; a nil latch refuses rather than panicking.

Both budgets are PROXY-WIDE. The per-session record tables with the proxy table as an aggregate parent, the per-route notice tables, the per-holder and per-site reserved floors, the per-source collapse windows, and the borrow/debt accounting that kept a floored write from being free were all removed: they cost several times the mechanism's own size to reallocate writes the suppression count already accounts for. The accepted residual is stated rather than closed — one session's dead upstream can spend a category's budget its siblings share, and one gateway tenant can spend a class budget its siblings share. `saturationGate` keeps its own per-pool, per-session episode collapsing for `RESOURCE_EXHAUSTED` records, where an episode rather than a rate is the finding, and its check-bucket-then-latch sequence is one critical section for the two races its lock-free predecessor had. Every rollup names its scope (`suppressed_refusal_scope: "proxy_category"` on a record, the class label and `proxy`-wide on a line), since one bucket serves several sites and a bare count gets misread; see `docs/threat-model-mcp.md` §3.7. Both transports route enforced requests through one shared `dispatchRequest` (`dispatch.go`: the method→handler mapping and fail-closed default) and the shared deny/forward/record core (`forward.go`: `enforcedForwardCore`/`forwardServerRequest`/`refuseUnroutable`), so the dispatch and enforcement logic live once instead of being hand-mirrored per transport — including the fail-closed routing refusal, whose two framings were the last pair with a bespoke record and now share one producer through that core, with its upstream sink REMOVED (a nil `callUpstream`, which the core AND `dispatchList` read as a MODE) so "never forwarded" survives a reclassification of the code that keeps the observe gate off it — the observe downgrade IS a forward, so a leg with no upstream cannot take it and the refusal stays hard with the code that names the real cause; a stub that FAILED on use looked equivalent and was not, since its error reached `recordUpstreamFailure` and wrote an `UPSTREAM_ERROR` deny for an upstream never contacted. A refusal for a message with no id builds no denial envelope for a caller that must discard one (`refusalResponse`, keyed on the id rather than a threaded flag, so the notification framing inherits it, with `refusalError` applying the same rule to the core's two plain-JSON-RPC-error refusal exits), and the rule is applied once more at the core's own BOUNDARY so all six exits obey it structurally rather than by which helper each reached for — the ALLOW tail included, which was the exception a comment had to remember. Both transports then SKIP a zero message rather than writing it (`mcp.RPCMsg.IsZero`, `writeDispatchResult`): `JSONRPC` has no `omitempty`, so an unconditional write puts the malformed frame `{"jsonrpc":""}` on the wire where nothing should have been sent; the leg that answers a blocked server-initiated initiator lives once too (`server_request_unblock.go`: `serverRequestUnblocker` + `trackServerRequest`, over the one nil-writer disposition `writeToInitiator` — which also BOUNDS the diagnostic every answering site writes, since a dead sink fails all of them at the peer's rate and a bound placed on one caller is one the next site added does not inherit — resolved LAZILY from the upstream's own sink so the holders that only want the tracker — every forwarded request, on a session that displaces nothing — pay nothing for a writer they never call. ANSWERING and RECORDING an answer that did not land are ONE obligation, so the unblocker carries the reporting wiring (`dropReport`: the leg's `refusalRecorders`, its `killSubject`, and this transport's `serverRequestLegs` vocabulary) and every answering site reports from it — the four arms that REFUSE a server-initiated request, and `unblock`'s three callers, which turned on a bool reporting whether the id was HELD rather than whether the answer LANDED and threw the delivery report away: a refusal record describes the refusal, not the delivery, so a destroyed answer left the upstream blocked with nothing on the tape (`catRefusalUndeliverable`, its own bucket since a broken sink needs no tracking, host or delivery to reach). The report is per DISPOSITION rather than per leg, because a destroyed answer eunox produced and a destroyed HOST REPLY are different facts carrying different categories, which is why one leg field could not serve both; `unblock` names its record from the tracker entry the take consumed, since its commonest caller holds a host RESPONSE and a response carries no method. The two params structs that take such a refusal hold that one unblocker rather than a writer, a bucket pair and a leg threaded separately, and both transports' entry-plus-dispatch sequence is one `dispatchServerRequest` in the `hostNotificationGate.admit` mould. The seam is the one the sampling leg's params and the pool's dispatch reach as well — those three fed the same sink from closures over a CONCRETE writer, and a nil `*mcp.MsgWriter` locks its mutex on a nil receiver, so they panicked after their audit record where the seam reports), since the four hand-written copies disagreed about the nil-upstream-writer case; `serialize.go` + `anchor_gate.go` hold the decision turn that orders a flow source's state write before a later sink's read — keyed on the state ANCHOR (the validated `mcp.task_id` under `taskAnchoredState`, the session otherwise) rather than on the connection, so two sessions sharing a task share a turn. BOTH transports resolve that anchor through `enforcement.ResolveStateAnchor`, the same resolver the engine's own key builder uses, so the turn and the state key cannot disagree about a request (stdio's FIFO ticket queues are keyed on it too — it resolves to one anchor today, and keying it is what keeps that from being an assumption held up elsewhere). Whether a policy needs a turn at all is `config.LocalManifest.NeedsDecisionTurn`, called from both transports rather than spelled out at each and DERIVED from the state class each token declares (`capability.TokenStateAccumulation`) rather than from a list of token types; the engine's two skip gates are NOT the transport's business at all: it hands the ENGINE the tokens the policy carries (`config.LocalManifest.PolicyTokens` → `enforcement.WithPolicyTokens`), a fact, and the engine intersects them with its own handler registry. Both registries' keyed-with-refcount lifetime is ONE generic (`keyed_registry.go`: `keyedRegistry[T]` + the embedded `keyedEntry`), with the reclaim trigger supplied by the embedder — the gate drops at its last holder, the FIFO also waits for the tickets it handed out — so a leak or lock-ordering fix has one home rather than two. The stdio server-initiated leg's wait for the turn is BOUNDED (`samplingTurnWait`, as HTTP's is) and its ticket is abandonable — the turn skips a ticket whose waiter gave up. That bound is a `turnWait` PAIR rather than one duration: `perHolder` refuses a waiter only when the request actually HOLDING the turn has held it a whole window without handing off (so a waiter queued behind a moving queue is not refused, which is the property the inline version had for free and concurrent handlers lost), and `total` is the ceiling that keeps "the queue is moving" from meaning forever, since a parked waiter holds a `serverRequestPool` slot. That leg also runs on its OWN goroutine rather than inline on the upstream reader, on BOTH transports, through one shared `serverRequestPool` (`server_request_pool.go`: admission bounded at `maxConcurrentServerRequests`, refusing-plus-recording `RESOURCE_EXHAUSTED` on saturation, plus the teardown `drain`) scoped proxy-wide for stdio and PER SESSION for HTTP: the reader is the only goroutine that delivers upstream responses, so a handler parked on the turn used to stall every in-flight call for the length of the bound, repeatably (HTTP's blast radius is one session rather than the proxy, and under `taskAnchoredState` the turn holder can be a different session sharing the anchor). The cost is that server-initiated requests have NO ordering guarantee among themselves, and each transport's teardown drains them (`awaitServerRequestsDrained` / `releaseSessionObjectState`) before releasing session state. A request reaches its turn through three tiers, every one of them addressed by the RESOLVED anchor rather than by a restatement of how the resolver decides, so all three are correct for any anchor kind rather than for the two that exist: the session's lock-free PIN (the gate for the anchor it resolved at registration, taken in `registerSession`, released by `releaseSessionObjectState` under the one teardown funnel `finishSessionCleanup`, whose id-KEYED half runs only for the id's last owner), which serves every request on a session-anchored route and every request of a task-anchored session that stays on one task; the session's own `gateCache` (`session_gate_cache.go`) for the OTHER anchors it resolves, since a session that SPANS tasks — the shape task anchoring exists for — matched the pin on nothing after the move and took the route-wide registry round trip on every enforced call for the rest of its life; and the route registry itself, the always-correct path, reached by a non-serialized route (where it is a no-op) and by a request racing its own session's teardown, after the cache has stopped admitting. Reaching the cap is NOT an overflow into that tier: the cache sheds its least recently used entry and serves the request, so a session cycling wider than the cap pays the cache's bookkeeping on top of the registry round trip rather than a wrong turn (measured, `BenchmarkDecisionTurn_SpanThrashing` against `BenchmarkDecisionTurn_Registry`). The pin is deliberately never RE-pointed: it is read with no lock at all, so moving it means returning the registry reference that is the only thing stopping that gate being reclaimed and rebuilt under a request which read the old pointer and has not yet taken its turn — two gates for one anchor is not slow, it is unserialized. The cache carries the synchronization that hazard needs: a request taking a turn on a cached gate is COUNTED for the whole turn, so eviction (LRU, capped at `maxCachedSessionGates`, because the anchors are validated task claims and one connection must not pin one gate per task it ever touched) never drops a reference in use — an entry with users is RETIRED, removed from the map so nothing new joins it, its reference returned by whichever request leaves last, and `gateCache.close` does the same at teardown for anything that outlives the bounded in-flight drain. On a task-anchored route a session may SPAN anchors — each host request is decided, keyed and serialized on its own — and what pays for that is the leg with no request in scope: `httpSession.noteRequestAnchor` records the span and `spansAnchors` makes the server-initiated leg refuse for the session's life (`session_spans_anchors`), because that leg decides from the claims captured at `initialize` while the host leg decides from each request's, and two tokens differing only in `task_id` would otherwise taint one bucket and peek another. The latch is taken for an ENFORCED request past every gate that can still refuse it — the same predicate the decision turn takes, since nothing else commits anchored state for that leg to peek past — and it is sticky for the session's life, so anything looser disables sampling for the connection permanently: taken above the framing branches, one POST of a frame that is neither request, notification nor response (no id and no method, which decodes fine) did it, as did a reply whose id this proxy never issued; taken above the in-flight cap, one saturating burst did; `initialize` routes through `dispatchRequest` too (its cross-cutting kill gate shared with the other locally-answered methods), with the per-transport response body supplied by an injected `buildInit` responder — only the HTTP *session-creating* `initialize` (no session/dispatchParams yet, and it carries the strict-audit gate) is answered outside the shared dispatcher. Gateway mode (top-level `transport: http` in config) multiplexes N upstreams on one `HTTPProxy`, each at `/mcp/<name>` with its own policy — per-route state lives in `route.go` (`UpstreamRoute`, built by `BuildRoutes`; its `routeSink` wraps the shared `*audit.Sink` and stamps the route name + policy version/digest), config parsing in `internal/config` (`GatewayConfig`; unknown YAML keys rejected; JSON Schema in `schemas/`). The package builds standalone on `internal/{audit,config,drift,mcp,pdp}` + `pkg/*`; the drift-check policy lives in `internal/drift`, and the transport imports it only for the `drift.CheckFunc` hook type (the binary injects `drift.MakeDriftCheck` as that hook, so the runtime calls the opaque hook and never references the comparison). Startup effects that overwrite SHARED last-writer-wins state (the control-token file, the session-kill TTL) run from each transport's own ready hook — `HTTPGatewayOptions.AfterListen` (post-bind) and `StdioProxyOptions.OnReady` (fired inside `Start` once the session is live) — never from the binary before the transport stands, so a proxy that fails to come up cannot clobber a running one. The exported seam the CLI consumes: `NewStdioProxy`/`StdioProxyOptions`, `NewHTTPProxyGateway`/`HTTPGatewayOptions`, `BuildRoutes`/`UpstreamRoute`/`LoadUpstreamPDP`/`LoadEffectReceiptVerifier`/`WrapRoutesWithJWT`/`AnyRouteAccumulatesSharedState`, the `Resolve*` flag resolvers, the control-token + OAuth-metadata helpers, `SetProxyVersion`, and the CLI-probe plumbing (`DoMCPHTTP`, `BuildUpstreamClient`, the revision-selected opener `UpstreamOpenRevision`/`BuildUpstreamOpenerWithID`/`ApplyUpstreamOpenerResult`/`UpstreamOpenerCompletion`/`DeclareUpstreamRevision`/`UpstreamHandshake`, `SessionHeader`, `IsInfraDenialCode`, `MaxUpstreamErrBodyBytes`, `BoundConsoleDetail`). Protocol-revision negotiation lives in `revision.go`: the host side is established per context — pinned from the FIRST resolved message the resolved revision actually DISPATCHES in the framing it arrived in, by the goroutine that reads messages, NOT from the `initialize` response (that placement left the flip refusal inert for any peer on a revision with no handshake, and raced the reader for a pipelined follow-up; the "dispatches it" half is what keeps the pin from being a wedge, since one id-less `initialize` declaring the revision that removed `initialize` otherwise latched a table with no handshake in it, unrecoverably — and the predicate reads the revision's own dispatch TABLES rather than the method's revision membership, because those two disagree exactly where the wedge lives: a request-framed `notifications/progress` names a method both revisions have and a message `dispatchUnmapped` discards) — and CHECKED per request against the `_meta` `io.modelcontextprotocol/protocolVersion` declaration, which is read by DECODING the params rather than scanning them for the key (JSON permits escaping any character of an object key, so a byte probe missed spellings the upstream reading the same forwarded bytes still saw) — the DUPLICATE-KEY rejection is a THIRD answer beside declared and absent (`mcp.ErrUndecodableDeclaration`), being the one decode failure eunox does not share with a conforming peer — the others stay plain absences, since invalid JSON is refused by every decoder and a shape mismatch carries no `_meta` object to read a declaration out of, so reporting them would refuse well-formed JSON-RPC with nothing to smuggle: the third answer is READ as absent only where something re-decodes the same bytes and denies them (a request routed to a `Decide` handler, whose target-bearing `INVALID_REQUEST` a version failure would replace, and whose manufactured absence is withheld from `checkDeclarationReachesUpstream`, that and a `*/list` REQUEST (`unreadParamsReachUpstream`) — since a peer otherwise adds a throwaway duplicate key to make this decoder bail, inherits the context past every gate, and leaves a clean revision but not pinned one while it answered that by hand), while a declaration that DISAGREES with its context is refused `UNSUPPORTED_PROTOCOL_VERSION` (-32022) rather than re-negotiated — and a refused host RESPONSE also UNBLOCKS the upstream request it would have answered (each transport's negotiation arm, through the one `serverRequestUnblocker`), since a protocol refusal is not an emergency stop and eunox can answer at its own revision without relaying anything the host said. That is the leg's ONE rule — eunox answers a blocked initiator wherever it can do so without acting on a second identity's behalf — and it has exactly two exceptions: a kill drop, deliberately left to be reclaimed with the session it is tearing down, and a reply the SESSION GATES refused, answered only when the sender is PROVABLY the session's own owner (`unblockGateRefusedServerReply` / `senderIsProvenOwner`), because answering completes the initiator's request whether or not the tracked id is consumed and so would hand a second identity a way to abort the owner's pending reply — and "proven" is not "not refused", since the owner binding is vacuous on a session with no bound identity while the audience pin refuses senders that binding never examines. - **`pkg/enforcement`** — the decision engine. Conditions are evaluated through a handler registry on `Engine`, whose entries carry a subsystem declaration alongside the handler (`registeredHandler`): a built-in takes it from the token's `pkg/capability` prototype entry, an override from `SubsystemDependent` if it implements it and is UNCLASSIFIED otherwise. An entry holds ONE of two shapes, never both — a pure `ConditionHandler` (`WithConditionHandler`) or a quota-consuming `CommittingConditionHandler` (`WithCommittingConditionHandler`), the latter carrying `PrepareCommit` alone and no `Handle`, so a committing condition has one entry point by construction rather than a second implementation the engine never calls. Its skip/commit contract is asserted in BOTH directions at the one site that consumes a `PrepareCommit` result (`commitDeferredConditions`), and the two violations are answered differently because only one is REPAIRABLE there: a skip the context did not authorize leaves the rest of the deferred set unchecked, so there is no verdict to stand in for it and it hard-denies; a bucket derived under `SkipQuota` is dropped, since the engine owns the only consumption point and dropping it IS the outcome a conforming handler produces for that posture — refusing would turn a third-party handler's bug into a hard outage on the one posture (`--audit`) whose whole contract is that it never blocks. Absorbed is not silent: the violations are named in `capability.EnforceResponse.HandlerFaults` as `{Type, Contract}` pairs — which handler, and which contract it broke, since a report naming only the condition type is unambiguous exactly while one repairable violation exists — the transport stamps them onto whatever record the decision produces (`audit.HandlerFaultKey`, through the one `decisionDetail` fold every below-decision exit shares — the posture that produces a fault is the one that FORWARDS a deny, so an allow-only report would go missing for the constraints whose second condition denies), and `eunox stats` raises them as an ATTENTION line. Those two assertions make the set uniform by construction, which is why there is no post-loop partial-skip guard to keep in agreement with them. The one statement of what a `HardDeny` in this package is FOR — where `WillForwardDeny` answers yes the transport forwards a downgradable verdict and blocks a hard one — lives on `WillForwardDeny` alone, and the forwarding half is pinned by a test in `internal/transport` rather than restated per refusal site. But WHICH refusals resist that downgrade is no longer the bool's question alone: a refusal the engine produced because it could not reach a verdict (an unmodelled condition type, a condition with no usable handler, an unwired or failing counter/store, a nonconforming backend index, a handler's unauthorized skip, a failed state commit) carries `capability.ErrCodeEnforcementError`, whose CLASS (`capability.ClassifyDenialCode`) is the whole encoding: `DenialInfo.Downgradable` folds it with the producer's override and is the ONE question every layer asks (the transport's `isObserveDeny`, the engine's redaction defer, and the PDP's `stamp`/`recordAuditModeAntecedent`/harden legs, which used to predict the transport's answer from the raw bool). Neither denial funnel derives the bool from the class any more — that made the field mean "override OR one of the two non-policy classes", two meanings a third denial constructor could get wrong on its own. Producers set it only to OVERRIDE the class — a policy verdict that must block anyway (`anchorUnresolved`, the two escalations, the descriptionHash pin). Every counter-backed KEY derivation reaches that class through ONE guard sequence (`counterSubjectGuards`, handed a `counterKeySpec` carrying only the condition type, key namespace and message tails; `quotaBucketKey` adds the target guard and observe skip on top for the two BUCKET derivations, and `handleSequenceBlock` stops at the shared sequence since it derives a history key), because the copies mirrored it line for line and had drifted at exactly the guards that matter: blastRadius classified an unwired counter a POLICY verdict, so an observing route downgraded it and forwarded the call with the cumulative budget neither checked nor counted, and sequenceBlock's third copy had no nil-request arm at all — a class a spec cannot choose is one the next bucket added cannot get wrong. The FLOW-label namespace takes the same guards' two corrections (`flowlabel.go`: its key is anchor-derived too, so the session gate refused a task-anchored request and its peek read "no labels carried" for a bucket that may hold them — a fail-OPEN at the sink — and its refusal was forwarded by an observing route with the sink never evaluated). The two structural `MISSING_CONTEXT` guards (no subject, no identifiable target) keep that CODE and carry `BlockOverride`, rather than the code being reclassified package-wide: `MISSING_CONTEXT` is a genuine policy verdict everywhere it reports a missing ARGUMENT, and moving it would break every rule keyed on it for a refusal that is one, while a bucket that was never derived has no verdict for an observing route to stand in for. The subject guard reads `e.resolveAnchor(req).ID`, not `req.SessionID`, so it cannot disagree with the key `anchoredKey` builds — gating on the session refused a task-anchored request whose bucket keys perfectly well, while `RecordSessionCall` (already anchor-gated) wrote for the same request, giving one request a subject in one namespace and none in the other; the message names `sessionId` unconditionally and provably so: `ResolveTaskVar` reports a task only for a non-blank claim, so a task-kinded anchor always has an id and only the SESSION fallback can reach this guard, while a task-anchored caller whose token carries no `task_id` is refused earlier by `anchorUnresolved` with the task-specific message. The nil-argument rule is the same shape one layer out, since a panic is the fail-OPEN reading of this package's own rule — a decision point that crashes produces no decision at all, and the supervisor decides the traffic: `nilSeamRefusal` is the one WORDING every refusing seam reports (so a support tape can be grepped for all of them, each naming only the arguments it actually takes), and the ANSWER is the shape its caller already fails closed on — an `EnforceResponse` from `nilRequestDenial` and from `CollectObligations`, an `error` from `PeekSessionLabels`, `BuildRegoInput` and `RecordSessionCall`, a `SourceCommitError` from `RecordSourceCall`, a `ConditionError` from `NonCommittingConditionVerdict` and `EvaluateAllowedValues`, and a nil constraint (this signature's own fail-closed answer) from `FindMatchingCapability` — with the CLASS single-sourced beside the wording, since the shape legitimately differs per seam and the class must not. `NonCommittingConditionVerdict` returns a verdict rather than the `ok=false` it used to fold this into: its one consumer renders that as "the deciding policy's handler commits state, or is not registered", every clause of which is false for a nil request, and a structured denial must not fabricate a cause. `RecordSessionCall` is the one whose old answer was fail-OPEN — its contract makes a nil return mean the marker WAS written, so a nil request short-circuited to "recorded" and a later `sequenceBlock` Peeked empty history. WHICH seams owe an answer is DERIVED from the sources rather than hand-listed (`nil_seam_coverage_test.go`: every exported func/method taking a `*capability.EnforceRequest` or `*capability.Constraint`, against a declared disposition table), because the hand-written list is what left four of them off. These are the seams a COMPOSING layer reaches, and they guard the RECEIVER too, a `ManifestPDP` legitimately holding no engine; a nil `matched` is refused in `recordLabels` rather than at the seam, because that is the only leg that reads it and refusing higher up turned a flow-skipping engine's antecedent-only commit into a hard deny. Every per-request check is threaded one `evalCtx{req, matched, requestID, now}` rather than the four-value tail seventeen signatures carried, so a new check on this path gets the decision's identity for free; the two exported denial builders reachable with no constraint in hand keep their explicit parameters. `bench_internal_test.go` holds the decision path's benchmarks (per-condition dispatch and its allocation-freeness, the two-pass structure, the anchored-key builders), runnable through `scripts/bench.sh`. `New` derives the two skip gates from that registry, intersected with the tokens the caller declares its policy carries (`WithPolicyTokens` — a fact about the policy; the retired `WithoutAntecedentRecording`/`WithoutFlowLabels` asked a caller for the conclusion, which a manifest-side derivation could get wrong for a replaced handler). The two extension points (`policy`, `custom`) answer from the wired `PolicyEvaluator` when it declares, rather than conservatively; pluggable `Clock`, `CallCounter`, `FlowLabelStore`, `EffectCeiling`, and `PolicyEvaluator` (external PDPs like OPA/Cedar) via functional options, the four INTERFACE-typed ones normalized to their ABSENT case at the option (`wiredOrAbsent`; `EffectCeiling` is a concrete pointer whose `== nil` read is already honest) rather than at each read: an option is the only way those fields are ever set, so one funnel settles what a TYPED nil means for every `== nil` read that routes to a fail-closed absent case — a nil boxed in the interface otherwise walked past all of them and panicked on the first method call, including inside `New` itself, since `policyConditionHandler` asks the evaluator which subsystems it reads. The clock is the one whose absent case is the DEFAULT rather than nil, having no fail-closed read to route to. `flowlabel.go` and `effect.go` hold the two axes' handlers, and `anchor.go` owns the ANCHOR every piece of accumulated state is keyed on — exported as `StateAnchor`/`ResolveStateAnchor`/`AnchorKind`, because a transport serializing decisions has to key its turn on the same subject the state accrues to and a second reading of "is this task-anchored" is where the two silently diverge (the two ENCODINGS differ on purpose: the engine's counter/store key keeps its session form byte-compatible with pre-anchoring deployments, `StateAnchor.Key()` is the in-process turn-registry key) — the session by default, or the validated `mcp.task_id` claim under `WithTaskAnchoredState` (opt-in; falls back to the session only for a request carrying NO token, refuses an authenticated one whose token carries no `task_id` rather than splitting its state across two buckets, and never shares state on the strength of something the caller did not prove). Every key builder routes through `Engine.anchoredKey`, so a new piece of accumulated state cannot be added under session keying while every existing one follows the task. The `effectCeiling` is NOT a condition: it runs once on the allow tail, after the matched constraint's conditions and BEFORE the session-state commit, so an over-ceiling call leaves neither a phantom `sequenceBlock` antecedent nor a stranded flow label. BOTH its arms are non-downgradable — `onExceed` picks the record an operator reads (a `CONDITION_FAILED` deny or the `decision: escalate` approval-queue entry), never whether the flagged action happens, so the deny arm carries `BlockOverride` rather than inheriting the policy class its code names and letting an observing route perform it. Both effect conditions and the ceiling read ONE `ResolveEffect` of the matched constraint's contract, threaded through the context, so they cannot disagree about what the call's effect was. The effect layer's verdict constructor is structural rather than a code picked per site: `effectDenial` TAKES the resolved effect (which is also where its details come from), so a refusal reached before the resolution — a `blastRadius` declaring neither bound, a non-numeric one, half a cumulative pair, or a `maxTotal` the float64 accumulator cannot represent (all four hoisted into `parseBlastRadiusBounds` above it precisely so they sit there); an `effectClass` with an empty or out-of-vocabulary `allow` set, or one with no contract in scope, which is what the exported non-committing seam always sees — physically cannot reach it and takes the package-wide `conditionFault` instead. One constructor hardcoding `CONDITION_FAILED` had made all of those downgradable, so an `--audit` route forwarded a call whose effect condition nothing evaluated. `conditionFault` (`engine.go`) is that fault code's SINGLE minter package-wide — held there by a source guard, since the same drift had left `timeWindow`, `ipRange`, `castCondition` and `sequenceBlock`'s declaration checks calling an unevaluable condition a policy verdict while their siblings called it a fault; a condition that names no argument to check keeps `CONDITION_FAILED`, that code being contractual for it in `pkg/capability/errors.go`. `ConditionError.Downgradable()` is the one question every reader asks of such a refusal, rather than the class or the override alone.
- **`pkg/callcounter`**, **`pkg/killswitch`** — in-memory and Redis backends behind a common interface (Redis enables multi-instance deployments; tests use miniredis). Redis CLUSTER is unsupported and refused rather than documented: `callcounter.NewRedis` returns an error for a `*redis.ClusterClient`/`*redis.Ring` (the library spelling) and the binary refuses a `--redis-addr` pointed at a cluster node after its startup ping (the operator spelling), because a SERVER-side cluster otherwise refuses `AdmitAll`'s multi-key `EVAL` with `CROSSSLOT` at the first policy carrying two quota buckets — fail-closed, so invisible until then — and a CLIENT-side `*redis.Ring` does not refuse it at all, which is worse and is why the type refusal rather than the request-time backstop is the load-bearing half. `killswitch`'s per-master SCAN stays for a consumer wiring that backend alone, and takes its topology straight from `redisutil.ClassifyTopology` — which returns the topology AND the per-server fan-out together, so a client one package calls sharding while the other has no iterator for it is unrepresentable rather than merely loud (the two hand-written switches this replaced had drifted, and a `*redis.Ring` fell through to a single-node SCAN that loads a partial kill set and reports healthy). The answer is THREE-valued because a concrete-type match has three outcomes: an UNRECOGNIZED type (a decorator, a consumer's own `Cmdable`) proves nothing, and folding it into "not sharding" is what let a wrapper around a cluster client enumerate one shard and report ready — fail-open, silent, on the emergency stop. BOTH consumers refuse it, in the shapes their signatures allow: `callcounter.NewRedis` returns `ErrUnknownTopology` and `killswitch.NewRedis` LATCHES it, reported by every reader and writer and fail-closed regardless of `--killswitch-fail-open` — with `WithSingleNodeKeyspace()` (both packages) and `WithShardFanOut()` (the kill switch's alone, a keyless SCAN being able to fan out where a multi-key `EVAL` cannot) as the declaration a consumer that knows what its wrapper wraps supplies, which is what makes refusing a legitimate wrapper tolerable — believed rather than checked BY THE CONSTRUCTOR, which performs no I/O, so `callcounter.CheckKeyspaceCoLocated` is the caller-run startup probe that checks it (one multi-key script written, every key read back individually, so a client routing the script to one shard leaves the rest unreachable; it also catches a proxy fronting a sharded backend, which `INFO` reports as a plain server, and which `CheckServerNotClustered` therefore cannot). Inconclusive is safe there, as it is for an unanswerable `INFO`, and a miss is re-probed with fresh keys before it is believed, an eviction not repeating where a shard placement does. Two residuals stay on the option: a declaration never probed over a wrapper fronting a Ring reproduces the split in full, and one over a wrapper holding a nil client constructs and panics on first admission, `IsNilClient` answering for a client that IS nil rather than for a wrapper around one. What the refusal does NOT bite is go-redis' own instrumentation: `redisotel` and the Prometheus hooks attach through `AddHook` and leave the concrete type alone. The counter admitted an unrecognized client until its stated reason was checked: the `CROSSSLOT` backstop covers only a SERVER-side cluster, and a client-side `*redis.Ring` shards over standalone servers that never raise one — go-redis routes an `EVAL` by its FIRST key, so the whole script runs on one shard and succeeds, and a bucket reached in another batch under a different first key accrues on the other server, each seeing part of the spend and the declared `maxCalls`/`blastRadius` bound enforced once per shard, silently, on the decision path. A declaration FILLS an unknown topology and never OVERRIDES a known one — that RULE is `redisutil.Reconcile`'s, one implementation for both backends with its nine cells tested once, since the two hand-written copies were the same switch in the same order and had already diverged on what each told an operator; what stays per package is the DIAGNOSIS, which genuinely differs (the counter must say a sharded keyspace has no declaration at all, the kill switch must name both of its options) and nilness, which is a question about the client rather than about a topology. Contradicting a recognized client is `ErrTopologyContradicted` in both packages (latched by the kill switch, returned by the counter), since honoring it would restore the very failure the refusal exists to prevent, reached through the escape hatch itself: a working fan-out discarded for a partial kill set, or a bucket's accounting split across shards. An AGREEING declaration is redundant rather than a conflict and keeps the CLASSIFIED side's iterator. The counter refuses either way, a sharding client being unusable to it regardless, so what the distinct sentinel buys there is the DIAGNOSIS: `ErrClusterUnsupported` would tell a consumer to wire the single-node client they believe they already declared. The topology is resolved ONCE at construction, so no enumeration re-asks a question whose answer cannot change — but that is a fact about the CLIENT and says nothing about any one PASS over it, which is the distinction the `*redis.Ring` arm lives in: go-redis skips a shard its heartbeat has voted down and returns nil, so `redisutil` wraps that iterator with a completeness check and a short pass surfaces as `killswitch.ErrIncompleteEnumeration` — bounded by the CONFIGURED shard count widened by the widest the ring has been observed to be, since `SetAddrs` leaves the configured count stale and under-counting is the fail-open direction, and refusing a pass over zero servers outright rather than accepting it as vacuously complete (the residual it cannot close: a ring GROWN while a shard is already down, which go-redis rebalances out of both `Len()` and the iterator with no memory that it existed). `killswitch.RingFanOut` exports the checked iterator for the decorator case, or the declaring option is a way back to the fail-open. Unlike its latched siblings that one is a REFRESH error and honours `WithFailOpen`, because a down shard heals where a wiring fault never does; the residual is `(*Ring).SetAddrs`, which reshapes a ring without writing back to the options the check reads, so a consumer that SHRINKS one at runtime declares its own complete fan-out. A TYPED NIL is classified unknown with no iterator: its per-server iterator is a non-nil func bound to a nil receiver, which would panic inside go-redis on the reconcile goroutine rather than returning the error the definition promises. That guard makes the ITERATOR honest but not the client — go-redis dereferences the receiver before it can build a reply, so every command on a nil client PANICS rather than erroring, and the first to run are `Start`'s `Subscribe` and the reconcile goroutine's `Get`, which is why a guard further down the call graph is unreachable. `redisutil.IsNilClient` (reflect-based over every nilable kind, so it needs no second type list; it answers for a client that IS nil, NOT for a decorator WRAPPING one — reflecting into the embedded field would falsely refuse a wrapper that legitimately forwards elsewhere, and probing would put a network round trip in a constructor that performs none) is therefore asked at each backend's construction seam: `callcounter.NewRedis` returns an error, and `killswitch.NewRedis` — whose signature returns none — LATCHES `ErrNilClient`, which `Start` refuses to launch on and which every reader and writer reports, fail-closed regardless of `--killswitch-fail-open` (fail-open trades revocation for availability during a TRANSIENT outage, and a nil client never heals). `ErrClusterUnsupported` stays in `callcounter`, where the reason for the refusal (the multi-key EVAL) lives. Every Redis writer ends with the pub/sub publish, so a publish that fails AFTER the durable write carries `ErrPublishFailed` (stamped in `publish` itself, whose contract already states the durable write has happened, rather than at each of the four callers) — the durable state IS written and replicas converge on the next reconcile tick, and a caller whose whole question is "did the revocation land" (`eunox kill`'s exit contract, `/control/kill`'s status) could not tell that from a write that never happened, so both reported failure forever on a Redis ACL granting SET/DEL/SCAN but not PUBLISH. That writers' rule is stated on the `Manager` interface beside the readers' confirmability rule. The request-time `CROSSSLOT` backstop matches go-redis' typed sentinel and `HasErrorPrefix`, not the reply text. `killswitch.Manager` carries `HealthStatus` — the readiness question asked with no request in hand, on the seam so a consumer holding the interface can distinguish "not ready" from "backend down" without matching backend-specific sentinels — and the confirmability rule (a backend that cannot confirm its kill set reports the cause from EVERY reader rather than serving a silent all-clear) is stated once on the interface and checked by a cross-backend conformance table. `InMemory`'s zero value is usable: the kill sets are created on first write, where they used to panic. It also carries `ObserveRevocations`: a kill has two effects and only one of them is a read, so a consumer learning of one through `ShouldBlock` alone can DENY the traffic but reclaim nothing the revoked session holds. Both backends notify (Redis from its pub/sub listener AND its reconcile commit, so a dropped publish still reclaims), the callback must not block but MAY call back in — which is a claim about every internal lock and not just the cache one, so BOTH lifecycle locks are released first: the reconcile commit returns the revocations it gained rather than delivering them (`refreshMu` is neither reentrant nor ctx-aware, so a callback reaching a refresh-taking method under it wedged the reconcile goroutine for the process's life and hung `Stop` on `wg.Wait`), and `Start` does the same with the initial snapshot's, since it holds `lifeMu` across its whole body and `Stop` takes that lock, and the `Revocation` is a trigger rather than a work list — the HTTP transport responds by re-asking about the sessions it holds. Every quota admission goes through ONE primitive, `AdmitAll(ctx, []capability.QuotaBucket)`, which admits a whole batch of buckets atomically or none of them. A bucket's `Counted` flag picks its accounting: entry-counting (backing `maxCalls`) or weight-summing (backing `blastRadius`'s cumulative `maxTotal`/`windowSeconds` bound). The two exist for COST, not expressiveness — a count is O(1) in both backends while a weighted total is summed per entry — and a single batch may mix them, so a capability carrying `maxCalls` alongside a cumulative `blastRadius` commits both in one call. What the manifest loader refuses is two buckets of the same kind on the same window (they would share one physical key); `checkDistinctBuckets` is the counter's own runtime backstop for the same shape. A lone `maxCalls` or a lone cumulative `blastRadius` commits through the same primitive as a one-element batch: there is no single-bucket method to drift from it.

The cache joins that predicate with its OWN staleness in `capability.KeyFetchHealth` (`FetchImpeded` — refreshes refused, so rotation is blocked and an unknown-`kid` token fails now — beside `Status`, the readiness verdict, which is impeded AND no servable set, since the breaker's cooldown is tens of seconds against a five-minute key TTL and degrading on the trip alone drains a fleet that is rejecting nothing). `internal/pdp.(*JWTPDP)` relays that verdict through `HealthStatus() error`, the ONE seam every degradable subsystem answers (`internal/transport`'s `healthReporter`, folded by `healthSnapshot.fold`, whose nil guard is reflect-based because an interface holding a typed nil is not nil and panicked the scrape) — the seam `*audit.Sink` answers too, through the `audit.Health` SAMPLE, so the counters `/healthz` renders and the verdict beside them are one reading and the maintenance carve-out lives with the state machine rather than being remembered by the transport, with each subsystem's DETAIL handed over separately — a seam widened to carry every detail would describe none of them, and reaching through concrete types for one subsystem while asserting an interface for the next is two precedents a third would pick between arbitrarily.

## Load-bearing invariants (from CONTRIBUTING.md)

- **Fail closed.** On any ambiguity — missing manifest, unmapped method, malformed JWT, unset condition argument — deny, with a structured error code (`AUTHORIZATION_FAILED`, `CONDITION_FAILED`, …), and log it. New code paths must preserve this.
- **Audit records are append-only and structured.** Never rewrite a record, never put free-form text in a structured field, never add a top-level field without updating the threat model (`docs/threat-model-mcp.md`).
- **No telemetry / background network activity** without explicit design discussion.
- **Pre-1.0: no backwards-compatibility shims.** Change manifest grammar, audit shape, or config keys cleanly and document the migration. Don't flag back-compat breaks as problems.
- **One static binary on purpose** — new runtime dependencies need strong justification.
- **No emojis in source files or code comments** (README/site are fine).
- Conditions match a specific argument name; never silently match alternatives.

## Conventions

- Every `.go` file starts with the two-line header: `// Copyright 2026 Eunolabs, LLC` + `// SPDX-License-Identifier: Apache-2.0`.
- **Comments explain WHY or HOW, never WHAT.** Delete a comment that just restates the line below it in words — if the code already says it, the comment is noise. Keep or write a comment only for the reason/tradeoff/constraint/bug behind a choice (WHY) or a non-obvious algorithm/ordering/concurrency requirement (HOW); cap it at one or two lines, no preamble, don't restate identifier names. Exported (capitalized) top-level `func`/`type`/`const`/`var` still need a godoc comment starting with their own name (`revive`'s `exported` lint rule requires it) even when there's no WHY/HOW to add — keep that lead-in minimal rather than padding it with restatement. If a comment asserts a rationale you can't verify against the surrounding code, mark it `// TODO: confirm rationale` instead of inventing one. License headers, TODO/FIXME with context, spec/issue links, and security warnings are always kept regardless of this rule.
- Conventional Commits (`feat:`, `fix:`, `sec:`, `perf:`, `refactor:`, `docs:`, `test:`, `ci:`, `chore:`; `!` for breaking). `refactor:` means no behavior change — a restructuring that also fixes observable behavior is a `fix:`. DCO sign-off required: `git commit -s`.
- Tests: a new EXPORTED func or method in `pkg/enforcement` taking a `*capability.EnforceRequest` or `*capability.Constraint` needs a row in `nil_seam_coverage_test.go`'s disposition table (and, unless it delegates to a guarded seam, a case driving it), since the walk there derives the seam set from the sources and fails the build for an undeclared one; new condition types need table-driven tests under `pkg/capability/` (allow + deny + malformed-input cases); new MCP method coverage needs a test in `internal/transport/enforcement_gaps_test.go` — including its PER-REVISION cells (which peer's revision dispatches it, which denies it fail-closed), since revision membership is declared on the method itself; only the table-DERIVATION machinery lives in `internal/transport/dispatch_revision_test.go`, the negotiation rule in `revision_test.go`, and the per-message gate order in `gate_order_test.go`; new audit-record fields need a sign-and-verify round-trip test; a new type answering the health seam (`HealthStatus() error`, whichever package owns it) needs a row in `internal/transport/health_conformance_test.go` declaring how a consumer HOLDS it — a sample it copies or the live subsystem behind a pointer — since that is what decides whether the fail-safe verdict is the type's own or fold's nil guard, and a source guard over every package in the module fails the build for an implementation with no row (or a row with no implementation); changing the duplicate-key scan in `internal/pdp` means keeping it in agreement with the tokenizer oracle in `scan_oracle_test.go` (equivalence table + fuzz targets, and a real fuzz campaign, not just the seeds — a campaign's coverage-distinct inputs are committed under `internal/pdp/testdata/fuzz/`, where `go test` replays them as seeds, so the next campaign starts where the last one finished rather than re-discovering the same ground).
- Every condition/directive discriminator declares THREE things on its `pkg/capability` prototype registry entry: the revision that introduced it (`Since`), the cross-call state its enforcement touches (`State`; see `tokenstate.go` for the rule, and note that an atomic `AdmitAll` budget accumulates but needs no decision turn), and the optional engine subsystems that enforcement reads (`Uses`; see `subsystem.go` — `SubsystemNone`, `SubsystemAntecedentHistory`, `SubsystemFlowLabels`, with the two extension-point tokens declaring everything because what an embedder's evaluator reads is not knowable here). An entry missing any of them fails the build (`TestTokenSince_…`/`TestTokenStateAccumulation_EveryRegisteredTokenDeclaresAClass`/`TestTokenEngineSubsystems_EveryRegisteredTokenDeclaresOne`) and is treated as the strongest class — and as depending on every subsystem — meanwhile. `internal/config`'s `checkTokenRevision` reads `Since` through `capability.TokenSince`, and a token with no `Since` is refused under every revision. A non-discriminator token (`effectCeiling`, a `${task.*}` value) has no registry entry and is gated inside `checkTokenGrammarVersion` instead. Either way it needs a test asserting it is REFUSED under `0.1` — that one gate is what keeps a later revision's predicate from silently widening an earlier one.
- Adding a condition or directive type also means adding a branch to `schemas/eunox-capability-manifest.schema.json`; `cmd/eunox`'s schema drift tests derive their expectation from the condition prototype registry, so a missing branch fails the build rather than shipping an undocumented token.
- Editing a `registry/contracts/` entry means recomputing its `digest`; `go test ./internal/registry/` fails otherwise, and so does any manifest that pinned the old value via `effect.ref`. A `blastRadius` `value` must also be spelled the way the manifest loader renormalizes it (`1`, not `1.0`) — the entry is refused at load otherwise, since the copy a manifest pins would digest differently.
- Behavior changes need a docs update in the same PR. Manifest grammar changes also update `docs/capability-manifest-guide.md` and the spec repo (`eunolabs/agent-capability-manifest`). Schema changes update `schemas/` plus a roundtrip test.
- Security vulnerabilities go through `SECURITY.md`, not public issues.
- Never reference issue numbers, bug IDs, or internal milestones (stages, phases, epics, sprints) in code comments, documentation, or site copy. Those references rot and belong in the PR description or commit message only.
